# Reserved retirement ownership

Native resource wrappers reserve a non-cloneable retirement ticket before native creation. The ticket owns one fallibly allocated node and its CPU-budget credit. Failure returns the credit before creating the native object; successful creation transfers it through resource ownership, submission and deferred destruction. Physical node storage is freed before its credit. Borrowed swapchain/timeline objects do not acquire native ownership.

Per-queue safe Rust AVL trees move existing nodes without allocating on enqueue or cross-queue migration. Commands reserve separate native-command and CPU-only-owner nodes. Setup detach/adopt moves the native ticket; failed wrapping/adoption frees or queues the original handle exactly once. Transient backing and query/descriptor/pipeline owners carry the same reservation protocol. No unsafe Send or global lock was introduced.

A GPU-completed command can still have a recording sibling in its host pool. Its unchanged payload uses the original node; per-queue persistent host-busy FIFOs alternate with newly completed nodes. Round-local owners are restored on return or unwind, so busy owners are tried once per round and a one-scan allowance still progresses across rounds. Full SyncSet checks remain mandatory even for retries. Destruction occurs after releasing queue locks. Bounded scan/destroy allowances are shared by each allocation attempt as described in pressure-reclaim-20261026.md; explicit shutdown retains its separate drain.

Allocator retiring/release paths no longer flush unrelated staged uses or clone the entire peak report. Released allocation metadata remains owned solely as deferred peak evidence until reporting or subsequent registration consumes it. Current reports exclude released entries; exact total-peak totals and allocation identities survive release, denied registration and independent device/system peaks. This retains metadata until that boundary; it does not retain GPU memory.

Scope limits: the public legacy raw-handle Device::retire compatibility entry has no pre-creation ticket and retains its synchronous HostOOM fallback. Internal native resource Drop no longer calls it. Arbitrary external raw callers therefore do not receive the reserved-path guarantee. One heap node per native payload and ordered-tree maintenance add construction cost and metadata; no overall memory or frame-time gain is claimed before A/B. The allocation counter uses the existing test System allocator for diagnostics, not the production mimalloc performance configuration. Window pressure/stability runs and all four-scene CPU gates remain open.
