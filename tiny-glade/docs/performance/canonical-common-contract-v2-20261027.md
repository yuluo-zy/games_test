# Prospective canonical common-v2 cold contract

Staging only. No actual source/tool changes, Cargo, target execution, GPU, ETW,
freeze, relocation of a real build, or historical reclassification was performed.

The first Rust batch is separate: `../canonical-layout-root-followup` provides
read-only getters, the exact shared helper, an optional rich hook and a distinct
mandatory common-v2 caller. This package does not replace the rich caller. A final
candidate must clone the entire final production tree after all correctness fixes;
an older isolated production tree plus selected host files is not a final candidate.

## Explicit contracts

- Historical common-v1 remains exactly three caller/probe/GPU files. The old
  `cab6757f...` standalone importer and six qualified runtime/measurement tools are
  unchanged. Their old artifacts, failures, original metadata and source identities
  are never upgraded.
- Formal common-v2 uses mandatory preparation on both separately frozen sources.
  It has exact four core paths, including
  `crates/tiny-glade/tests/support/performance_sparse_layout.rs` (not a sibling of
  cpu_measurement/mod.rs), plus four shared input dependencies: performance_input,
  performance_workload, test-support mod and upload_wait. They must have identical
  known bytes on both sides.
- Five getter source files and original_gameplay_chain.rs are each bound to their
  own source.json SHA and archived full bytes. The exact reviewed getter additions
  and boot function body must agree; unrelated whole production/test files may
  differ across baseline/candidate. This is a finite audited fixture closure, not
  an automatic Rust dependency parser or proof that arbitrary raw integer escapes
  can be discovered at runtime.
- Optional rich canonical diagnosis uses a separate source contract
  `rich-optional-canonical-source-diagnostic-v1`, no formal harness value, and its
  exact rich caller hash. `preparation_stamp` is shared structure/association
  validation only. A rich controller still must prove explicit flag=1, diagnostic
  eligibility and frozen binary/source identity. It cannot claim formal common-v2.

## Cold tool changes

`perf_canonical_contract.py` is a pure source/archive/stamp validator. Its formal
`source_contract(source_files, raw_files)` requires the complete 14-path reviewed
set. `rich_source_contract` accepts only the distinct rich caller; neither API
converts one caller into the other. Empty owner allocations are valid; owner_count
need not be bounded by occupied chunks. Counts obey actual Brick typed capacity,
and the stamp is associated with both raw input endpoints. It describes once-only
preparation, not the final/all-frame layout or verified BLAKE3/GPU/pixel contents.

`perf_headless_workload.py` adds explicit capability/source-review-v2 support.
All existing native/partial-upload/overflow/receipt validations and incomplete
all-upload/indirect coverage remain intact. A v2 capability and source review must
contain the same `canonical_source_contract`, generated by the pure validator from
their exact archived files and source.json. Each of `canonical.OBLIGATIONS` must be
true in the independently authored source-review report, in addition to every
pre-existing producer-review field. The source set is still exact and findings
must be empty. A boolean report is never a substitute for that source review.

`perf_headless_series.py` declares the selected harness, shared source closure,
both own-source contracts and validator module SHA. It checks these at declaration,
validation/evaluation and raw workload proof; audit seals contain the selected own
contract and retain plan/raw artifact binding. Changed/deleted source archives or
capability/review artifacts fail cached validation as well as replay. Mixed v1/v2,
rich/formal or importer/harness versions are rejected. Thresholds, clocks, AB/BA/AB,
600/3000, cost-shift flags and incomplete-workload pending status are unchanged.

`perf_import_frozen_bundle_canonical.py` is a new standalone v2 verifier, selected
only by an exact whole-code SHA allowlist in series. Its embedded validator must
be byte-identical to the separate module (tested). The new import archive retains
all 14 original source bytes, with own source identity and exact contract in the
import plan/manifest. Cold verification uses this local archive after the original
checkout advances/disappears. The unchanged builder still emits
`headless-frozen-build-v1`; every original freeze file remains unchanged and the
derived build differs only in executable path. The old v1 verifier is not edited.

## Delivery and validation

Only the four tool payloads in manifest.json are implementation files. The two
existing-file patches are exact review aids; new module/importer files are copied
as their exact LF bytes. `delivery-manifest.json` additionally binds the three new
test/runner files, two small source fixtures and this document (10 targets).
`apply_tools.py` defaults to read-only preflight and checks every target and payload
SHA before writing any delivery target. No runtime tool, Rust product source,
common template, original frozen metadata or historical importer is a target.
Root authorizes and owns any actual application.

`run_regressions.py` uses the unchanged existing synthetic v1 tests and these new
cold contract/import controls. The relocation tests use fake, non-executable EXEs,
temporary synthetic Git repositories, and explicitly synthetic source fixtures.
Their pass is not a native build, complete source audit, GPU acceptance or CPU gain.

Actual application (by Root only): run `python -B apply_tools.py --root C:\\game`
from this staging directory, then add `--apply` after inspecting its complete
preflight. Actual regression command is
`python -B C:\\game\\tools\\run_canonical_contract_regressions.py`.

Real fresh-process complete owner coverage, full BrickDrawList/native workload,
visibility/payload/pixels and four-scene stability remain required before a new
formal Release comparison. Later continuous/local wall reallocations may drift;
the fixture does not repack on each frame or freeze edits to hide that work. Old
invalid pairs remain invalid. No CPU gain, 16ms, strict pixels or final completion
is established by this package.
