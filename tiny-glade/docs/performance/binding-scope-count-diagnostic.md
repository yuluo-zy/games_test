# Binding scope count experiment

This is a candidate-only rich diagnostic. The frozen common baseline/candidate harness, its three byte-identical files, the existing 13 management fields, the four existing algorithm controls, and six CPU runtime-policy tools stay unchanged.

The narrow fixture patch adds a preallocated `Vec<BindingScopeProbeCounts>` only in `cpu-probe` builds. `TG_CPU_BILL=1` captures one Copy snapshot for each existing successful observation; all JSON conversion happens after the measured endpoint. The top-level `binding_scope_reuse_enabled` reports the actual getter's algorithm flag. Feature-off reports `null`, not an invented boolean. Row `binding_scope_bill` retains raw cumulative callbacks, Vec growth events, sum of capacity bytes after growth, snapshot builds/hits, shape fallback callbacks and failed callbacks, plus validity and actual mode. Invalid/overflowed or failed bills cannot pass.

`perf_binding_scope_diagnostic.py BUILD_LABEL SERIES` controls two processes of the same frozen EXE in OFF, ON order. Defaults are the existing static scene, 60 warmup frames and 30 CPU-observation intervals (31 raw rows). It reuses the existing `perf_headless.capture` fixture and ready/go handshake. The environment wrapper adds `TG_BINDING_SCOPE_REUSE=0/1` only after inherited TG/RHAPSODY settings were cleared, keeps the rich bill enabled, and removes stage logs/GPU timing. Validation remains explicit. Existing four management modes retain their defaults. Frozen EXE/PDB/DLL/source identities and controller/dependency hashes are checked before and after each process.

The controller requires exactly one successful test and zero ignored tests, rejects Vulkan validation diagnostics, verifies the requested mode against both the top-level getter and every row, and checks complete CPU receipt associations. Both raw input endpoints/trajectory, workload script, native API/copy classifications, graph/Collect work, draw-list lengths and actual submitted upload deltas must match exactly. Raw manager/device IDs are checked within each process and excluded from cross-process semantic equality. Reset, regression, missing proof or generation changes invalidate the comparison.

Measured counter totals are the last minus first observation, so warmup and the initial CPU baseline observation are excluded. Binding callbacks and snapshot opportunities must still match. `vec_capacity_bytes_after_growth_sum` measures the sum of capacities after growth events; it is not live memory, total allocation traffic or allocation CPU cost. `reuse_hit_observed` reports whether the cache path had actual hits, without assuming it must be beneficial.

The result explicitly sets `diagnostic_only=true`, `cpu_performance_evidence=false`, `clean_cpu_acceptance=false`, `production_16ms_acceptance=false` and `formal_source_A_B=false`. It reports no millisecond/percentile gain and does not start ETW. A later clean ETW algorithm ablation needs a separately named controller and evidence series. GPU pixel correctness and formal source-baseline A/B remain independent acceptance tasks.

Every child leaves its normal `headless-runs/SERIES-off` or `-on` directory. `run.json`, `session.json` and `fixture.log` receive SHA256 sidecars, including failed validation paths. Series progress records attempted runs before launching them, so a failed second mode stays discoverable. Existing runner/controller functions are restored after each environment override.

The integrated controller has 12 passing Python tests, including successful and rejected two-capture mock runs. The binding implementation has 6 passing ownership/budget tests and 9 passing sampler catalog tests, including a real Vulkan page/epoch invalidation test; all counts exclude ignored tests. Logs are `.perf/binding-scope-controller-tests.log`, `.perf/binding-scope-cpu-tests-fixed.log`, and `.perf/binding-scope-sampler-tests.log`. The first budget test run failed because its fixture used budget zero (unlimited); two fixture budgets were corrected to one byte without changing production or assertions. The rich integration fixture still requires serial compilation and the real same-frozen-binary OFF/ON run. This implementation remains an experimental performance candidate until clean CPU benefit and independent correctness gates pass.
