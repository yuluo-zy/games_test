# Versioned downstream upload cache

The actual country-core `rg_buffer_copy_from_slice_u32` consumer now accepts an explicit `UploadContentVersion`. Complete content carries a session-stable source identity and version; unknown content uses ordinary dynamic staging. Existing recovered business callers explicitly pass Unknown rather than inventing unavailable camera/history/scene versions.

Tiny `GraphPasses.with_session(&mut session)` borrows the existing frame session only during declarations. Its complete-content route calls the production `cached_result` API and declares producer/consumer subgraphs with complete resource ports and ranges. It retains the original graph scope and actual GPU owners. The cached output is an immutable GPU upload source; the mutable business destination is still copied each frame. The cache key includes every supplied byte as well as the explicit version, so a missed version bump cannot return stale contents.

The identity-bound strict Vulkan test runs seven frames each with result/subgraph caching enabled and disabled, including three warm hits, a version change, a same-version byte change, and an explicitly unknown upload. Every output is compared against the requested words and the uncached reference. The test asserts three result hits, three misses, one version invalidation, a Parameters miss for the missed version bump, and at least three subgraph analysis hits despite unrelated whole-graph changes. The unknown upload does not request or publish a result-cache entry. Zero Vulkan validation errors and zero skips.

Whole-plan, subgraph-plan, and persistent-result cache statistics now expose fixed `CacheDiagnostics` counters. `CacheReason::ALL` is bounded (23 entries); reasons distinguish cold/disabled/unknown lookups, full-key fields, dependency invalidations, capacity eviction, explicit cleanup, pressure, and canceled pending outputs. No dynamic-name intern table or per-frame event log is added. A key with multiple differing fields reports a primary actual mismatch; counters do not claim all fields changed independently. Capacity admission rejection remains separately reported by existing `rejected_oversized` storage statistics.

This report proves correctness and production wiring for the complete CPU upload-source boundary. It does not assert that arbitrary compute/raster results or unknown business inputs are automatically cacheable, or replace the final unified matrix and performance gates.

CPU verification: rhapsody all-features library tests 280/280; country-core default-feature `render::rg_helpers` tests 6/6. The separate country-core all-features test build reached native linking but is BLOCKED because optional native-audio requires unavailable external FMOD libraries (`ld: library fmod not found`). Its exact log is preserved; the default-feature pass is not reported as all-features acceptance. The final unified harness retains country all-features type-checking as a separate gate.
