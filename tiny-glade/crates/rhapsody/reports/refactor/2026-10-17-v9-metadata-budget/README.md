# Managed resource metadata admission

The existing typed weak `ResourceManager` now uses the device allocator account: its own shared state and live `ManagedInner` allocations are live CPU bytes, and the actual generational slot backing remains cached CPU bytes until the store dies. Allocation is fallible, with `OutOfHostMemory` for host budget/reservation failure and `Timeout` at the configured live-entry limit. The store holds allocator statistics rather than a strong Device edge. Last-owner removal releases the slot mutex before raw resource destruction, including rejection paths.

Raw Buffer, Texture and TextureView payload reservations stay inside the actual resource, so an escaping `Arc<T>` continues to hold its credit. All normal and transient native-object creation pre-reserves metadata; transient binding receives an already reserved ticket and introduces no new failure after ownership transfer. Device initialization prepares the statistics and both stores before VkDevice creation. Graph binding preserves typed allocation errors through the recording failure channel.

The existing slotmap dependency was moved from 1.0.6 to 1.1.1 because stable `try_reserve` is nightly-only in 1.0.6. country-core uses the same workspace pin; unrelated dependency updates were excluded.

Validation: **27/27 PASS** across six identity-bound binaries (20 actual Vulkan cases and 7 CPU cases), no skips, zero validation errors/VUID/SYNC-HAZARD. This includes native/suballocated GPU budget accounting alongside the independently charged CPU baseline, escaping resource/view ownership, admission refusal before native growth, concurrent weak-key churn, bounded managed views, and the late named-resource failed-name capacity regression.
