# 综合播放器性能定位与第一轮优化

相同 Apple M3、120 帧、240 FPS 请求、完整 GPU 像素校验及 Khronos 同步验证下串行测量：

| 配置 | 实际 FPS | p95 帧耗时 | p99 帧耗时 |
|---|---:|---:|---:|
| 原调试构建 | 7.04 | 238.18 ms | 293.74 ms |
| 优化 CPU 参考算法/复用后，同调试配置 | 19.56 | 103.65 ms | 132.51 ms |
| 同源码，仅播放器 opt-level=3；框架/依赖仍为 dev | 38.73 | 41.37 ms | 46.28 ms |

主因是原建筑参考逐像素扫描全部矩形，约 81 ms/帧；改为独立 CPU 行区间绘制、完整版本键复用，仍每帧逐字节比较。64 种版本组合与旧逐像素 oracle 完全一致。旋转光栅只缓存 24 个角度的独立 CPU 覆盖掩码，不缓存 GPU 输出，每帧继续比较所有实际像素。

新增四路构图、提交、等待/回读、校验的独立累计计时。原 build_and_begin_frame 包含全部生产者执行，graph_framework/GPU command 时间仅含最后合成，不能把后者当整个场景成本。优化播放器后，上传准备仍约 6.92 ms/帧，四路提交约 4.61 ms，等待/读回约 3.12 ms；此后优先合并生产者图/提交与异步校验流水线，不宣称已经实现。

25 项 CPU 测试（含全部版本对照）通过。所有三次真实 GPU 检查无 validation error/warning，退出资源归零。该组为短程定位，未控制温度/系统噪声、未预热 300/采样 3000/重复三次，不能替代 V9 性能门。初始两个调试基线没有另存二进制，不冒充身份完备的正式 A/B；优化播放器二进制与 SHA 已保存。
