# rhapsody 交付计划与窗口验收规范

本文件定义 rhapsody 重构的交付范围、版本顺序、Window Lab 验收场景与门槛。目标结构与不变量见 [ARCHITECTURE.md](ARCHITECTURE.md)，剩余任务见 [REFACTOR_PLAN.md](REFACTOR_PLAN.md)，当前状态与证据见 [REFACTOR_PROGRESS.md](REFACTOR_PROGRESS.md)。

V0–V9 是交付版本，不是 crate 的语义版本。版本条目描述的是验收门槛，不表示对应功能已经完成；完成状态只由 REFACTOR_PROGRESS.md 登记。

## 1. 范围与完成边界

本计划覆盖：统一错误、设备与队列、完成与回收、提交事务、呈现生命周期、图编译分层、类型化与版本化资源、帧局部池、异步上传与读回、预算与背压、整图/子图/结果缓存、瞬态内存着色、bindless 与动态渲染、异步管线编译与热重载、多队列调度、独立的正确性检查器。

以下不是本轮完成的前置条件，属于独立后续实验：GPU 驱动绘制、mesh shader、程序化建模迁到 compute、descriptor buffer、shader object、GPL。

工作方式：每版按 **接口与不变量 → CPU 测试 → 接入 Window Lab → GPU / 窗口测试 → 性能对比 → 报告** 推进。旧路径在对照验证完成前保留，验收后删除。每版能独立启动 demo、退出并释放全部资源。只通过编译不算通过，只通过 CPU 测试也不算 GPU 验收。

硬件、驱动或权限不支持的验证必须标为 BLOCKED 或 UNSUPPORTED，不能以跳过伪装成 PASS。必做的硬件路径缺验证时，对应里程碑不能 PASS。

完成条件：M0–M9 满足下文门槛；S01–S08 各有有效运行记录；下游迁移与旧路径删除完成。

## 2. 核心接口与职责

| 模块 | 输入 / 输出 | 必须保证 |
| --- | --- | --- |
| Device / ExecutionPolicy | 能力查询、队列需求 → 实际启用配置 | 一个设备归属与代际；不把“支持”当作“已启用”；同一物理队列只有一个锁和一条时间线 |
| FrameTransaction | 已录制批次 → 成功批次的完成点集合 | GPU 提交成功不可逆；先预留回执与退役容量；未提交的命令取消，已提交的资源延迟回收 |
| PresentLifecycle | acquire 租约 → present ticket / 显式释放 | 二值信号量只消费一次；渲染完成与呈现资源可回收分别证明 |
| GraphDefinition | 版本化资源访问、pass、副作用 | 句柄属于当前图；读取必须有来源；访问范围与读写类型明确 |
| CompiledPlan | 声明 + 显式能力与策略 → 符号化调度与屏障 | 不持有 Vulkan 对象、用户回调或时间线值；缓存键完整可比较 |
| FrameInstance | 计划 + 本帧导入资源 / 参数 → 录制与提交回执 | 绑定时校验实际资源、初态与设备代际；引用存活至使用完成 |
| TransientMemoryPlan | 生命周期偏序 + 实际内存需求 → backing / offset / 别名依赖 | 同时使用的资源不重叠；一个 backing 只有一个释放责任；不破坏默认并行性 |
| Upload / Readback | 有界区间申请 → ticket / `try_read` | 复用区间前等待相关使用；正确 flush / invalidate；与新 GPU 提交互斥登记 |
| BudgetController | live / in-flight / cache / retiring 字节 → 淘汰或背压 | 不淘汰在飞资源；预算包含各 worker 的局部池；OOM 不被隐藏 |
| ResultCache | 内容版本 + 参数 + shader 版本 → 持久输出 | 依赖变化即失效；命中仍带完成依赖；输出不进入普通瞬态着色 |

帧协议：准备导入与上传 → acquire → 构图与绑定计划 → 录制 → 逐批提交并立即登记 → present → 分别回收 GPU 与呈现资源。acquire 之前允许完成与交换链无关的 CPU 准备，以缩短持有图像的时间。

## 3. 共用验收 demo：Window Lab

入口：`cargo run -p rhapsody --example window_lab -- ...`。Windows 走 Win32 + rhapsody Vulkan，macOS 走 AppKit / CAMetalLayer。窗口与业务测试素材解耦。其他平台未接入时必须明确退出，不能静默转为 headless。

demo 直接调用生产的图执行与交换链接口，不维护第二套渲染后端。场景与播放器在各版本之间保持同一输入协议，便于 A/B 对照。

### 3.1 测试素材与场景

| 编号 | 内容 | 主要检测 | 验收版本 |
| --- | --- | --- | --- |
| S01 | RGB 色条、灰阶、棋盘与角标 | 色彩通道、方向、缩放、上传与读回一致 | V0 |
| S02 | 固定步长移动图形与图像播放列表 | 持续提交、暂停 / 单步 / 切换、帧序与动态内容 | V0 |
| S03 | GPU 光栅旋转三角形 / 网格 + 后处理 | shader、附件、管线、动态渲染正确性 | V3，V7 扩展 |
| S04 | temporal 乒乓与显式历史 reset | 首帧、resize、失败帧的历史有效性 | V3 |
| S05 | 可调数量与尺寸的瞬态附件链 | 峰值显存、着色复用、多帧隔离 | V6 |
| S06 | 局部变化的建筑网格 / 阴影 / 文字夹具 | 子图失效、内容版本与结果缓存 | V5 |
| S07 | 大批上传 + 延迟读回 + 受限预算 | 背压、公平性、非一致性路径、OOM 收尾 | V4 |
| S08 | graphics / compute / transfer 依赖链 | 真实多队列、ownership 与别名偏序 | V8 |

V0 素材使用仓库内确定性图案与 PPM 图片列表，不依赖网络或视频解码器。验收逻辑不能依赖有损视频的逐像素相等。S06 可先使用版本化几何夹具，不以实际建筑资产为前置。

持续综合场景 `--scene showcase` 是默认负载：每帧同时运行细分旋转网格与后处理、上一帧历史预览、局部建筑 / 阴影 / 字形更新、大批上传与多队列计算，GPU 合成后呈现。普通播放以较低频率穿插缩放、最小化恢复与效果资源更新；密集 WSI 压力单独保留为显式选项。四路 producer 与最终合成均需验证真实输出。单纯的窗口尺寸变化不能替代该负载。综合场景中的等待与读回属于正确性成本，性能验收使用隔离负载。

### 3.2 操作与自动化协议

- 窗口标题显示当前场景、播放 / 暂停、帧号、后端版本与验证层状态。键盘：Space 暂停，N 下一素材，Right 单步，Esc 退出。
- CLI：`--playlist <json>`、`--frames <N>`、`--fps <N>`、`--script`、`--report <json>`、`--capture <ppm>`、`--require-validation`。未指定 `--frames` 时持续播放；自动运行使用固定步长与有限帧数。
- `--script` 自动缩放、最小化与恢复，并记录实际发生的事件。后续扩展 JSON 场景脚本，覆盖历史 reset、效果开关、预算、热重载、错误注入与队列策略。
- 故障注入只在 demo 或测试 adapter 中启用，按“阶段 + 第几次调用”确定触发；生产 API 不暗藏随机失败。
- 自动验证 GPU 离屏输出与 CPU 已知输入，并另做实际交换链截图或窗口检查。离屏读回通过不等于窗口最终像素已验证，报告必须分别记录。
- 场景切换、关闭与异常退出都要收尾。未支持的场景或开关必须明确拒绝，不能被当作已运行。

### 3.3 验收产物与退出码

每次验收生成 `report.json`、错误与验证层消息，以及至少一张 GPU 读回图。窗口实测另附截图与检查记录。报告包含：代码版本、提交与 dirty 状态；命令行；fixture 哈希；设备、驱动、API 与启用能力；验证层可用性；帧数；窗口事件；像素比对；CPU 阶段耗时；GPU 查询结果；预算、缓存与回收峰值；结果原因。未实现的指标写 `null` 或 `unsupported`，禁止填 0 冒充已测。

退出码 0 表示本次请求的检查全部通过。运行失败、像素不符、验证层 error、强制验证层缺失均返回非零。窗口人工检查状态单独记为 pending / pass / fail，不影响离屏检查的记录。

## 4. 分版验收门槛

### V0：窗口实验台与可重复基线

- **交付**：独立 example、内置播放列表与 PPM 素材、暂停 / 切换 / 单步、有限帧模式、窗口 resize / 最小化 / 恢复脚本、JSON 报告与 GPU 读回保存。
- **验收**：至少 300 帧，遍历全部默认素材；真实窗口呈现成功；GPU 读回逐字节一致；script 各事件实际发生；正常关闭；验证层 error 为 0（缺层只记为未验证，`--require-validation` 下失败）。
- **边界**：当前使用的保守等待与逐帧命令分配必须在 README 中标明，不宣称达到最终吞吐目标。V0 不代表新的呈现生命周期或性能优化已完成。

### V1：唯一设备、精确使用与统一回收

- **交付**：统一错误分类、唯一 `Device`、实际队列规划、每队列时间线、资源 last_use、`Retirement`、设备代际。
- **验收**：提交失败不发布完成点；等待未提交的点被拒绝；两个独立队列互不被全局锁阻塞；旧句柄与跨设备句柄被拒绝。Window Lab 连续 1000 帧，资源、命令与诊断计数热身后不单调增长。
- **边界**：不允许全局 queue lock、镜像提交状态或 CPU 补发完成信号。资源层不得形成 Device 与 Arc 的强引用环。

### V2：事务提交与真实呈现闭环

- **交付**：`FrameTransaction`、`AcquiredImageLease`、`PresentTicket`、交换链代际；demo 接入生产 `FrameLoop`，主图与呈现由同一执行协议提交。
- **验收**：在 acquire 之后、录制中、首批与后续提交、present、回收各步骤逐一注入失败；无错误地复位在飞资源；无重复释放或重复消费；可恢复错误在下一帧成功。100 次 resize 与 20 次最小化 / 恢复无验证层 error；关闭时资源归零。
- **边界**：DeviceLost 不伪装为可继续，停止提交并完成可执行的清理。真实设备丢失不通过破坏用户驱动测试，只用测试 adapter 注入，并单独标明。
- **呈现证明**：`Strict` 默认。有 maintenance1 时使用 present fence；无 maintenance1 时使用 `QueueIdle`，其保证弱于 fence，只能作为兼容路径，不能对外声明与 fence 等价。

### V3：图分层、资源契约与独立检查

- **交付**：`GraphDefinition` / `CompiledPlan` / `FrameInstance`，类型化图 ID，设备与图归属，资源写版本与子资源访问范围，纯规划接口，独立检查器。
- **规则**：裁剪以导出与副作用为根；原地写保留真实反依赖；错误声明不 panic，非法首次读取、类型不符与范围越界在提交前拒绝。
- **验收**：随机小图与保守执行输出一致；未知来源读取被拒绝；未消费且无副作用的 pass 被裁剪，有副作用的 pass 保留。S03 光栅与 S04 历史 reset 在窗口中可见，并有 GPU 参考结果。
- **产物**：可读的图计划转储、契约单测、旧编译与新编译的对照记录。

### V4：帧局部池、异步传输与预算

- **交付**：帧 × worker × family 命令池，描述符过渡池，CPU arena，Upload / Readback ticket，区间占用协议，`BudgetController`，有界后台队列。
- **预算**：区分 live、in-flight、cache、retiring，局部池计入总量，高低水位防抖。压力下先清空闲缓存，再延后低优先级任务；绝不淘汰 GPU 在飞资源。
- **验收**：S07 容量耗尽后可恢复；non-coherent 范围的对齐与可见性有测试；host 写入与并发提交无竞态；正常帧不出现 device 或 queue idle。GPU 帧槽完成前的 reset 被拒绝；内存回落到配置的缓存水位。
- **性能门**：预热后固定图的框架临时分配目标为 0 次/帧；素材解码与报告分配单列。记录 p95 / p99，不以平均值掩盖背压尖刺。

### V5：整图、子图与结果缓存

- **V5a 整图**：规范化完整键，覆盖所有烘焙输入、编译器版本、能力与队列；哈希只用于定位，命中后比较完整键。绑定时重算动态边界。条目数与字节数有上限，并记录失效原因。
- **V5b 子图**：`SubgraphInterface` 与稳定局部计划；全局统一处理跨子图同步、队列与内存放置。局部缓存不得固化全局偏移或完成值。
- **V5c 结果**：内容版本、参数、shader 实现、相机 / 光源 / 历史等依赖驱动失效；命中仍登记产出完成依赖；输出转为持久资源，受预算控制，并排除普通瞬态着色。无法完整声明依赖的 pass 拒绝结果复用。
- **验收**：强制哈希碰撞不误复用；内容、结构、shader、设备代际的改变分别正确失效；稳定图预热后结构编译次数为 0；只改一个子图时其余子图的计划命中。S06 检查实际执行与跳过次数及像素，不只看命中计数。
- **性能门**：缓存开关 A/B，键构造与边界协调成本计入总 CPU。子图划分无收益时保持整图策略并记录结论；子图与结果功能本身仍需验收，不能因无收益而省略。

### V6：瞬态内存着色

- **交付**：真实 requirements 查询，兼容分组，带 size / alignment 约束的贪心放置，backing owner，别名切换的同步。
- **策略**：默认 `PreserveParallelism`，只复用依赖已能证明不并发的区间；导入资源、temporal、持久导出、结果缓存与 dedicated 资源排除在外。跨帧槽的物理区间互不覆盖。
- **验收**：S05 开关的像素一致；构造已知可复用案例，验证实际 committed 字节减少；同时存活、类型或对齐不兼容的资源不得重叠；首次未初始化读取被拒绝；backing 只释放一次。额外同步不得为默认策略新增依赖边。
- **产物**：生命周期与偏移转储，实际峰值与碎片，分配次数，p95 / p99。不以统一的“节省 N%”替代案例与硬件实测。

### V7：动态渲染、bindless 与异步管线

- **能力合同**：列明最低必需的 feature 位与 limits；基础模式与 bindless 模式分别检查。不因硬件支持某扩展就启用未实现的路径。必需路径不支持时明确返回 `Unsupported`，并保留硬件验收缺口。
- **动态渲染**：光栅与管线使用 rendering attachments；S03 与参考输出对照。
- **bindless**：全局堆、索引、视图与 shader 参数协议，覆盖 sampled / storage image、buffer、sampler 与实际 limits；槽位在全部使用完成后才归还。
- **异步管线**：请求同键合并，后台队列有界，未就绪时使用声明的 fallback 或跳过策略，热路径不得同步编译。磁盘缓存校验版本与设备标识，原子保存，损坏时安全重建。
- **热重载**：帧边界发布新版本；失败时保留旧管线；旧对象安全退役；shader 变化传播到结果缓存失效。
- **验收**：S03 连续变体切换与合法、错误 shader 的热重载；错误保留旧管线；在飞 descriptor 槽不被提前复用；坏缓存不崩溃；同键只编译一次；动态渲染与参考输出一致。
- **性能门**：渲染线程同步创建管线次数为 0；记录首次与稳定帧的 p99，以及后台队列峰值。

### V8：多队列与全局调度

- **交付**：`QueueClass` 分批，release / acquire ownership，跨队列时间线依赖；内存着色按 happens-before 偏序扩展。
- **策略**：别名队列退化为单队列，不额外制造同步。默认保留并行性。若引入 `MinimizeMemory` 类策略，必须先校验无环并报告关键路径代价。
- **验收**：S08 在真实独立族上输出一致、时间线独立推进、同步验证无 error；不同完成顺序不会提前回收；跨队列同时使用的资源不得别名。Off / Prefer / Require 与 Exclusive / Concurrent 分别覆盖。
- **硬件门**：只有单队列或别名队列的机器只能完成 CPU 与别名队列验证，M8 标 BLOCKED（缺硬件），不能宣称多队列验收通过。

### V9：收敛、下游与发布验收

- **删除**：替代后的旧设备、生命周期、编译、屏障与呈现路径，兼容桥，原版布局单测与地址注释全部删除。demo 只使用正式接口，不保留独立优化引擎。
- **下游**：`tiny-glade`、`tg-text`、实际调用 rhapsody 的 `country-core` 宿主、shader 包与相关测试统一使用正式接口。
- **正确性长跑**：S01–S08 全部通过；至少 30 分钟且不少于 10000 帧；稳定负载、效果切换与缩放压力分别测。无验证层 error、像素回归、未解释挂起与无界增长。
- **性能**：同机、同驱动、同负载。预热 300 帧，采样不少于 3000 帧，重复 3 次。分别记录框架 CPU / GPU 与 vsync 等待。默认策略的 p95 / p99 若回退超过约定阈值（初始 5%），必须定位并修复或关闭该优化；阈值小于噪声时扩大采样。
- **最终报告**：功能矩阵全部 PASS，支持的硬件矩阵完成，下游构建与测试全绿；每项优化有开启与关闭的数据、限制与回退方式。任何未验证的硬件路径或未关闭的正确性缺陷都保留为未完成。
