## 1. 完成边界与工作方式

本计划覆盖：统一错误/设备/队列、统一完成与回收、提交事务、呈现生命周期、图编译分层、类型化与版本化资源、帧局部池、异步上传/读回、预算与背压、整图/子图/结果缓存、内存着色、bindless/动态渲染、异步管线编译及热重载、多队列和独立正确性检查器。

每版按“接口与不变量 → CPU 测试 → 接入窗口 demo → GPU/窗口测试 → 性能对比 → 保存报告”交付。旧路径在对照验证完成前保留，验收后才删。每版能够独立启动 demo、退出并释放资源；不能用只编译通过代替运行通过。

GPU 驱动绘制、mesh shader、程序化建模迁到 compute、descriptor buffer、shader object 不属于本轮完成的必要条件：它们是独立的后续实验。基础能力、缓存、内存着色和多队列调度属于本轮；硬件不支持的验证必须标为 BLOCKED/UNSUPPORTED，不能以跳过伪装 PASS。

## 2. 核心接口与职责

| 模块 | 输入 / 输出 | 必须保证 |
| --- | --- | --- |
| Device / ExecutionPolicy | 能力查询、队列需求 → 实际启用配置 | 一个设备归属和代际；不把支持当作已启用；同物理队列只一个锁和时间线 |
| FrameTransaction | 已录制批次 → 成功批次完成点集合 | GPU 提交成功不可逆；先预留回执与退役容量；未提交取消，已提交延迟回收 |
| PresentLifecycle | acquire 租约 → present ticket / 显式释放 | 二值信号量只消费一次；GPU 完成与呈现资源可回收分别证明 |
| GraphDefinition | 版本化资源访问、pass、副作用 | 句柄属于当前图；读取有来源；访问范围与读写类型明确 |
| CompiledPlan | 声明 + 显式能力/策略 → 符号化调度和屏障 | 不持有具体 Vulkan 对象、用户回调、时间线值；可比较的完整缓存键 |
| FrameInstance | 计划 + 本帧导入资源/参数 → 录制、提交回执 | 绑定时校验实际资源、初态和设备代际；引用存活至使用完成 |
| TransientMemoryPlan | 生命周期偏序 + 实际内存需求 → backing/offset/别名依赖 | 同时使用不重叠；一个 backing 只有一个释放责任；不破坏默认并行性 |
| Upload / Readback | 有界区间申请 → ticket / try_read | 重用区间前等相关使用；正确 flush/invalidate；与新 GPU 提交互斥登记 |
| BudgetController | live/in-flight/cache/retiring 字节 → 淘汰/背压 | 不淘汰在飞资源；预算含各 worker 局部池；OOM 不被隐藏 |
| ResultCache | 内容版本 + 参数 + shader 版本 → 持久输出 | 依赖变化失效；命中仍带完成依赖；输出不进入普通瞬态着色 |

帧协议：准备导入/上传 → acquire → 构图/绑定计划 → 录制 → 逐批提交并立即登记 → present → 分别回收 GPU 与呈现资源。允许在 acquire 前完成与交换链无关的 CPU 准备，缩短持有图像时间。

## 3. 共用验收 demo：Window Lab

入口：`cargo run -p rhapsody --example window_lab -- ...`。Windows 首版走 Win32 + rhapsody Vulkan；窗口与业务测试素材解耦。其他平台未接入时必须明确退出，不静默 headless。

demo 直接调用实际 rhapsody 的图执行和交换链接口。V0 允许“离屏主图 → 展示提交”两个阶段和保守等待，报告标记 baseline；V2 起迁到生产 FrameLoop，禁止长期维护第二套优化渲染后端。场景与播放器跨版本保持同一输入协议，便于 A/B。

### 3.1 测试素材与场景

| 编号 | 内容 | 主要检测 | 首次要求 |
| --- | --- | --- | --- |
| S01 | RGB 色条、灰阶、棋盘与角标 | 色彩通道、方向、缩放、上传/读回一致 | V0 |
| S02 | 固定步长移动图形和图像播放列表 | 持续提交、暂停/单步/切换、帧序与动态内容 | V0 |
| S03 | GPU 光栅旋转三角形/网格 + 后处理 | shader、附件、管线、动态渲染正确性 | V3，V7 扩展 |
| S04 | temporal 乒乓与显式历史 reset | 首帧/resize/失败帧历史有效性 | V3 |
| S05 | 可调数量/尺寸的瞬态附件链 | 峰值显存、着色复用与多帧隔离 | V6 |
| S06 | 局部变化建筑网格/阴影/文字夹具 | 子图失效、内容版本与结果缓存 | V5 |
| S07 | 大批上传 + 延迟读回 + 受限预算 | 背压、公平性、非 coherent 路径、OOM 收尾 | V4 |
| S08 | graphics/compute/transfer 依赖链 | 真实多队列、ownership 和别名偏序 | V8 |

V0 素材使用仓库内确定性图案与 PPM 图片列表，不依赖网络下载或视频解码器。PNG/JPEG 或视频可后续接入素材解码适配器；验收逻辑不能依赖有损视频逐像素相等。实际 3D 建筑资产不是 V0 前置条件，S06 可先用版本化几何夹具。

持续综合播放场景 `--scene showcase` 作为默认可见负载：旋转细分网格与后处理、上一帧历史预览、局部建筑/阴影/字形更新、大批上传和多队列计算每帧共同执行，在 GPU 合成后呈现。普通播放以较低频率穿插缩放、最小化恢复和循环效果/资源更新；密集 WSI 压力仍单独保留。四路 producer 与最终合成均需验证真实输出，单纯窗口尺寸变化不能替代此负载。此场景的等待/读回属于正确性成本，性能验收继续使用隔离负载。

### 3.2 操作与自动化协议

- 窗口标题/后续 HUD 显示当前场景、播放/暂停、帧号、后端版本、验证层状态。键盘：Space 暂停、N 下一素材、Right 单步、Esc 退出。
- CLI：`--playlist <json>`、`--frames <N>`、`--fps <N>`、`--script`、`--report <json>`、`--capture <ppm>`、`--require-validation`。未指定 frames 时持续播放；自动运行用固定步长和有限帧数。
- V0 script 自动缩放、最小化/恢复，记录实际发生的事件；后续版本扩展 JSON 场景脚本，增加历史 reset、效果开关、预算、热重载、错误注入与队列策略。
- 故障注入只在 demo/test adapter 中启用，按“阶段 + 第几次调用”确定触发；不在 release 生产 API 暗藏随机失败。
- 自动验证 GPU 离屏输出与 CPU 已知输入；另做实际交换链截图/窗口检查。离屏读回通过不等于窗口最终像素已验证，报告分别记录。
- 场景切换、关闭和异常退出都应收尾；未支持的场景/开关明确拒绝，不能被当成运行过。

### 3.3 验收产物

每次验收生成 `report.json`、错误/验证层消息、至少一张 GPU 读回图；窗口实测另附截图及检查记录。报告包含：版本/提交及 dirty 状态、命令行、fixture 哈希、设备/驱动/API/启用能力、验证层可用性、帧数、窗口事件、像素比对、CPU 阶段耗时、GPU 查询结果、预算/缓存/回收峰值和结果原因。未实现的指标用 null/unsupported，禁止填 0 冒充已测。

退出码 0 表示本次请求的检查通过；运行失败、像素不符、验证层 error、强制验证层缺失均非零。窗口人工检查状态单独为 pending/pass/fail，不影响把离屏检查如实记录为 pass。

## 4. 分版交付与里程碑

### V0 — 窗口实验台与可重复基线（M0：看得到、测得到）

- 交付：独立 example、内置播放列表与 PPM 素材、暂停/切换/单步、有限帧模式、窗口 resize/minimize/restore 脚本、JSON 报告与 GPU 读回保存。
- 实现边界：复用现有 device / graph / swapchain；不修改主线程正在重构的核心模块。当前保守等待和逐帧命令分配必须在 README 标出，不宣称达到最终吞吐目标。
- 验收：至少 300 帧，遍历全部默认素材；真实窗口呈现成功，GPU 读回逐字节一致；script 各事件实际发生；关闭正常；验证层 error = 0（缺层仅记未验证，强制模式失败）。
- 产物：demo README、测试素材、运行命令、首份实测报告。M0 不代表新的呈现生命周期或性能优化完成。

### V1 — 设备与完成状态收敛（M1：只有一套完成真相源，对应 P1–P3）

- 交付：统一错误分类、唯一 Device、实际 QueuePlan、每队列 timeline、资源 last_use、Retirement、设备代际。
- 迁移：所有生产提交/呈现入口受正确队列锁保护；删全局 queue_lock、镜像提交状态和 CPU 补发完成信号；资源层持有关系避免 Device 缓存与 Arc<Device> 循环。
- 验收：提交失败不发布完成点；等待未提交点被拒绝；两个独立队列互不被全局锁阻塞；旧句柄/跨设备句柄被拒绝。demo 连续 1000 帧，资源、命令与诊断计数热身后不单调增长。
- 产物：旧机制删除清单、CPU 失败注入结果、GPU timeline 结果、V0 同负载对比。

### V2 — 提交事务与真实呈现闭环（M2：失败后下一帧可用，对应 P5 提前闭合）

- 交付：FrameTransaction、AcquiredImageLease、PresentTicket、交换链代际；demo 接生产 FrameLoop。主图与展示工作由同一执行协议提交。
- 提交前预留回执/退役记录，成功后不可失败地登记；部分成功保存资源真实终态；未提交取消，已提交延迟回收。错误清理保留主错误。
- 呈现：按图像管理 present 二值信号量；maintenance1 fence 与无扩展代际回退分别建模。acquire 未消费/已消费、补救布局转换、释放图像与信号量收尾分开处理。
- 验收：在 acquire 后、录制中、首批/后续提交、present、回收步骤逐一注入失败；无错误复位在飞池、无重复释放/消费；可恢复错误下一帧成功。100 次 resize 与 20 次最小化/恢复，无验证层 error；关闭时资源归零。
- 限制：DeviceLost 不伪装可继续；停止提交并完成可执行的清理。真实设备丢失不靠破坏用户驱动来测试，使用测试 adapter 注入，单独标明。

### V3 — 图编译分层和资源契约（M3：可缓存的计划不带帧状态，对应 P4）

- 交付：GraphDefinition / CompiledPlan / FrameInstance，类型化图 ID、设备/图归属，资源写版本与子资源访问范围，纯规划接口与独立检查器第一版。
- 拆开当前 compile_graph 的分配、物理映射和规划；实际内存需求作为不可变输入给后续放置器。渲染回调通过 FrameInstance 绑定。
- 裁剪以导出和副作用为根；原地写保留真实反依赖。错误声明不 panic，非法首次读/类型/范围在提交前拒绝。
- 验收：随机小图与保守执行输出一致；未知来源读取被拒绝；未消费且无副作用的 pass 被裁剪；副作用 pass 保留。S03 光栅、S04 历史 reset 在窗口可见并有 GPU 参考结果。
- 产物：图计划可读转储、契约单测、旧编译与新编译对照报告。

### V4 — 帧局部池、异步传输和预算（M4：稳态分配与等待可控，对应 P3/P4）

- 交付：帧 × worker × family 命令池、描述符过渡池、CPU arena，Upload/Readback ticket、区间占用协议、BudgetController 与有界后台队列。
- 预算区分 live/in-flight/cache/retiring，局部池计入总量；高低水位防抖。压力下先清空闲缓存、延后低优先级任务，绝不淘汰 GPU 在飞资源。
- 验收：S07 容量耗尽可恢复；non-coherent 范围对齐与可见性测试；host 写入与并发提交无竞态；正常帧无 device/queue idle。GPU 帧槽完成前 reset 被拒绝；内存回落到配置缓存水位。
- 性能门：预热后测框架热路径分配；目标为固定图的框架临时分配 0 次/帧，素材解码和 demo 报告分配单列。记录 p95/p99，不以平均值掩盖背压尖刺。

### V5 — 整图、子图与结果缓存（M5：未变化的工作真正复用，对应 P4/P7）

- V5a：规范化完整键 + 整图缓存，哈希定位后比较完整键；烘焙状态入键，动态边界在绑定时重算。
- V5b：SubgraphInterface，稳定局部计划缓存；全局协调跨子图同步/队列/内存放置。
- V5c：内容版本驱动结果缓存；输入、参数、shader 实现、相机/光源/历史等实际依赖传播失效；输出成为持久资源，命中仍有完成点。
- 验收：强制哈希碰撞不误复用；稳定图预热后结构编译次数为 0；只改一子图时其他子图计划命中；只改素材内容不重编结构但结果缓存失效；修改 shader、设备代际拒绝旧条目。S06 检查实际执行/跳过次数与像素，不仅看 hit 计数。
- 性能门：缓存开关 A/B；键构造、查询、边界协调成本计入总 CPU。子图划分无收益时保持整图策略，记录结论，不做无上限缓存。

### V6 — 瞬态内存着色（M6：省内存且无隐性串行退化，对应 P4）

- 交付：真实 requirements 查询适配、兼容分组、带大小/对齐约束的贪心放置、backing owner、别名切换同步。
- 默认 PreserveParallelism 只复用已有依赖证明不并发的资源；导入、temporal、持久导出/结果缓存和 dedicated 资源排除。跨帧槽物理区间互不覆盖。
- 验收：S05 着色开关像素一致；构造已知可复用案例验证实际 committed 字节减少；同时存活、类型/对齐不兼容资源不得重叠；首次未初始化读取被拒绝；backing 只释放一次。额外同步不使默认策略增加依赖边。
- 产物：资源生命周期/偏移转储、实际峰值与碎片、分配次数、p95/p99。不以统一“节省 30%”替代案例与硬件实测。

### V7 — 管线与描述符路径（M7：变体切换不阻塞渲染，对应 P4/P7）

- 交付：dynamic rendering、bindless 延迟回收、持久管线缓存、异步编译队列、帧边界热重载发布。能力探测决定可选实现；最低支持特性明确写入 README。
- 管线请求同键合并；后台队列有界；未就绪使用已声明的 fallback 或跳过策略，不能热路径偷偷同步编译。磁盘缓存校验版本/设备标识，损坏安全重建。
- 验收：S03 连续变体切换/合法及错误 shader 热重载；错误保留旧管线；在飞 descriptor 槽不提前复用；损坏缓存不崩溃；同键只编译一次；动态渲染与参考输出一致。
- 性能门：渲染线程同步管线创建次数为 0，记录首次/稳定帧 p99 和后台队列峰值。GPL/descriptor buffer/shader object 不是验收前置。

### V8 — 多队列与全局调度（M8：独立硬件队列实测，对应 P6）

- 交付：QueueClass 分批、release/acquire ownership、跨队列时间线依赖，内存着色按 happens-before 偏序扩展。
- 别名队列退化为单队列，不额外制造同步。默认保留并行性；MinimizeMemory 策略新增依赖前检查无环并报告关键路径代价。
- 验收：S08 在真实独立族上输出一致、时间线独立推进、同步验证无 error；随机不同完成顺序不提前回收；跨队列同时使用的资源不得别名。Off/Prefer/Require 和 Exclusive/Concurrent 策略分别覆盖。
- 硬件门：仅单队列机器时可完成 CPU/别名队列验证，但 M8 标 BLOCKED（缺硬件），不能宣称全项目验收完成。

### V9 — 全链路收敛与发布验收（M9：全部范围关闭，对应 P7）

- 删除已替代旧设备/生命周期/编译/屏障路径，迁移 tiny-glade 与 tg-text；demo 使用正式接口，不保留独立优化引擎。
- 验收：全部 S01–S08；30 分钟窗口长跑且至少 10000 帧，稳定负载/效果切换/缩放压力分别跑；资源、缓存与诊断均在预算内；无验证层 error、像素回归、未解释挂起及增长。
