# 资产库工程化与修复（2026-10-18）

本轮针对 `country-core/src/asset_libraries` 的六项审查问题修复代码，按用户要求优先保证功能、正确性和可维护性，允许调整原设计。没有新增依赖版本，没有重新逆向原二进制，不把本轮工程化结果计为原作恢复进度。

## 实现结果

| 审查问题 | 实现 |
|---|---|
| CPU 影子可能读取填充字节 | `ShadowedBuffer<T>` 的擦除接口要求 `bytemuck::NoUninit`，用检查型切片转换；ResourceHandle 按字段构造，移除布局强转 |
| 纹理/描述符空实现假成功 | 所有设备操作返回 Result；旧未连接适配明确失败；TextureHost 接既有托管纹理、视图缓存、setup 上传和 BindlessHeap |
| D16 清零长度错误 | 复用渲染库已恢复格式表，长度检查溢出，清零 mip 0 的全部数组层 |
| 预设描述丢失 | 创建时保存完整描述，图导入接口必须传描述；修正普通预设为 2D，显式单 mip、单层 |
| 热重载和 VAO 更新缺少消费者 | runtime 注册有序系统，GameFrameDriver 在 PostUpdate 执行；解析错误保留旧状态，VAO 失败保留重试 |
| 瞬态回收没有生产调用 | 真实 GameLoop 安装相同宿主的资产资源，每帧回收 CPU 网格与实际 GPU 缓冲 |

额外修正：删除 mesh 同时清路径/名字/脏记录；缺失 mesh 不再登记修改；别名冲突先验证再提交；调色板候选构建和 CPU 发布保持原子性；Create/Rename 通知支持编辑器原子保存；句柄计数器耗尽后不回绕。

## 实际调用链

真实宿主：`GameLoop::new` → `CoreRenderBridge::install_asset_libraries` → world 中的资产资源和 AssetLibraryRuntime；`GameFrameDriver::new` → PostUpdate 的 Reclaim → Reload → Rebuild → 当前帧渲染读世界。

- 回收：实体析构入队 → 锁外批量删除 → mesh 清索引 → 创建宿主释放 VAO 缓冲。回调展开时批次守卫归还未完成项。
- 网格：文件事件 → Result 解析/校验 → 成功替换 CPU mesh → 合并脏记录 → 构建 VAO → 成功发布，释放旧缓冲。
- 纹理：文件事件 → 安全解析编译资产 → 真实 TextureHost 创建 → 替换同一资产下标 → 释放库内旧采样租约及宿主旧身份。
- GPU 描述符：首次查询 → BindlessHeap 实际分配和写入 → 保存租约及实际 GPU 下标；命令保留自己的租约，重载后旧槽位等待在途使用完成才回收。可注入设备的延迟提交路径在失败时保留 pending。

原测试为修补描述丢失另造的 `PresetRg` 与描述表已删除，pass_kit 测试直接消费生产库传出的完整描述。

## 性能与可读性

固定 25 项预设改用稠密向量；不为未修改对象重建缓冲；脏通知排序/去重；回收及通知队列复用容量；文件 I/O 与资源删除在通知锁之外执行；JSON 向量使用 serde 从借用值直接解析，移除按属性序列化类型字符串和逐顶点临时向量。

源码以中文解释业务约束，使用候选调色板、描述符、存储缓冲、视图解析等明确命名。移除生产代码中的指令偏移、对象布局表、历史错误清单和重复实现，原证据保留在项目 evidence/历史报告。

没有做 FPS、帧耗时或内存峰值基准，不声称已有量化性能提升。GPU 热重载回归会检查库内旧租约释放，防止旧纹理随重载永久积累。

## 设备兼容与行为变化

首次真实 GPU 测试证实本机不接受原版大小的 8163 项完整布局（8160 sampled + 其他表各 1；保证支持值为 1212）。宿主改为复用 BindlessHeap 的真实布局支持检查，按需缩小 sampled 容量；库使用实际后端分配结果，不猜测原版常量或递增 GPU 槽位。硬件不足返回明确错误。

本轮主动改变原版/旧翻译行为，包括错误后的部分写入、删除后的路径残留、空 mesh 保留旧 VAO、读写锁升级后重复分配、失败消耗索引、锁内删除及仅接收 Write 的事件过滤。旧指令差分、布局和源码指纹报告不覆盖当前实现；它们作为历史证据保留。

缓存 DescriptorIndex 的消费者须在资产变化后重新查询；渲染命令须按 rhapsody 协议保留并登记租约。资产描述符表不替代 shader 反射、参数绑定或完整游戏渲染调度。

## 联编时的工作区情况

工作区已有其他改动在进行，最初 --locked 检查要求更新已有 tiny-glade 依赖边。锁文件仅补入已声明的 bytemuck、tg-text、walkdir 三条边，没有新增包或升级版本。country-core 的 bytemuck 声明统一为 workspace 配置，启用已有的 derive 特性，支持当前共享存储类型的 Pod 合同。

为完成当前宿主联编，修正了三个小型既有接口问题：TemporalRenderGraphState::clear 被 cfg(test) 隐藏却由生产方法调用；production_resolve 按值传 RasterPipelineKey 并正确转换 anyhow 错误；mei_host 移除对 u32 的第二次 raw()。其他聊天产生的 loading_graph、owned texture import、frame_setup 和 UI 类型接线主体不计为本轮实现。本轮在新帧消费者出现后补齐只读名字/采样视图快照接口，并对齐完整纹理描述与现有缓冲查询接口；没有重复构造其帧流程。
