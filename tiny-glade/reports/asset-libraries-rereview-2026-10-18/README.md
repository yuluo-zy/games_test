# 资产库第二轮审查与修复（2026-10-18）

范围为当前 `country-core/src/asset_libraries` 全部 15 个 Rust 文件，并沿网格解析、VAO 创建、SSBO 初始上传、TextureHost 与帧参数消费者检查资源生命周期。沿用用户授权：功能和正确性优先，允许修改逆向设计。本轮属于源码工程审查，没有新原进程差分或原作等价恢复信用。

## 确认问题与修复

| 优先级 | 问题及触发条件 | 修复 |
|---|---|---|
| P1 | `add_new_with_data<T>` 只有 Copy 合同，通过原始字节 helper 上传带填充类型，仍可能读取未初始化字节；上一轮只约束了 CPU 影子视图 | 初始上传要求 `NoUninit`，使用 bytemuck 转换。已有元素通过 derive 验证，启用既有依赖的 min_const_generics 特性支持数组；添加带填充元素编译失败测试 |
| P2 | 普通 `AssetMeshLibrary::remove` 仅删除 CPU 资产；没有实体或 TransientMesh 时，维护系统不会释放对应 VAO 和宿主缓冲 | CPU 删除登记独立通知，Reclaim 阶段使用同一宿主释放 VAO；缺设备时保留通知，重复删除幂等，不每帧扫描整个库 |
| P2 | 延迟描述符表发布后，每次替换清掉资产索引，却不会回收 next；一张纹理连续重载即可耗尽 8160 个槽 | 延迟后端复用已有槽位并重新登记 pending；提交读取最新资产，多次替换合并。真实 BindlessHeap 路径仍使用不可变租约与 GPU 延迟回收 |
| P2 | `get_rg_buffer` 先返回缓存再检查类型；同短名其他类型在缓存命中时可绕过完整类型校验 | 类型校验放在所有缓存分支之前，写锁取得后再次检查缓存，避免锁升级期间重复导入 |
| P2 | `rebuild_vao` 声明返回 Result，缺失 CPU mesh 时却 expect panic | 改为返回错误，保留库状态，不创建缓冲；更新原来断言 panic 的测试 |

## 回归范围

- 普通 mesh 删除后没有实体仍回收 GPU 缓冲；临时移除宿主后通知保留，恢复宿主只释放一次。
- 延迟描述符在首个提交前多次替换，并在首次发布后连续重载 8192 次，始终复用一个槽位，每次提交使用最新物理纹理身份。
- 已有 VAO 在设备创建失败时保留旧缓冲和待重建标记；下一帧成功更新并释放旧缓冲。
- SSBO 已缓存图句柄时仍拒绝同短名不同类型；拒绝后原类型仍可命中原句柄。
- NoUninit 编译失败测试验证带隐式填充的类型不能通过本模块初始上传入口。

## 集成调整与边界

仅为 NoUninit 约束给已有调色板、RT、自动对焦记录及测试替身增加 derive；使用已有 RockyTerrain 的 Pod 合同，没有新增依赖包或版本。初次编译被并发修改中的 `save/load_game.rs` 错误返回类型阻断，补了 `anyhow::Error -> LoadGameError` 的现有 From 转换，不改变状态行为。其系统随后由其他任务改为返回 BevyError，本轮移除临时注册适配，按最新签名继续验证。JSON 网格加载器在其他任务中增加了位置属性校验，本轮仅将自己的热重载 fixture 改成包含有效位置属性的网格，不覆盖其实现。

旧成功记录不会冒充本轮最新源码的测试结果；首次失败日志保留。全部游戏、所有 watcher 平台及原进程行为不在此次验收范围内。下层通用存储缓冲的所有字节转换入口未在本轮全量收紧，NoUninit 安全结论仅覆盖本模块的初始上传与影子读取接口。

验证期间遇到共享 Cargo 构建锁、并发存档系统签名变化、另一个任务移除临时 GPU 探针、磁盘空间不足。保留对应失败日志，不计为通过。磁盘处理只清理了未锁定的旧增量编译会话，以及 40 分钟以前的旧 country-core 归档/元数据；没有删除源码、资产或测试证据。清理明细随报告保存。
