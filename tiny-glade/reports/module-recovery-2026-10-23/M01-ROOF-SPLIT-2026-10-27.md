本轮先实际读取原 B 同路径 `crates/systems/decorator/src/ui_systems/handle_splitting_roof_decorators.rs`，再恢复现有文件。原入口是 `try_display_roof_decorator_parts_and_get_hovered_part_id@14127a790`（2854B）与 `handle_moving_out_roof_decorator_part@14127bab0`（2996B）；三个工厂闭包在 `14127b570/14127b730/14127b8f0`，目的地闭包在 `14127c7f0`。没有创建业务目录。

## 原有缺口与恢复结果

旧显示入口把部件位置固定为零，只按光标欧氏距离选择，部件循环数量还少一个；写入的是不能唤醒真实网格的raw记录。拖出入口是空函数。旧签名没有真实命中、屋顶组件查询、派生资源、ID生成器、归档、历史和操作事件，无法完成业务链。

当前显示链是：真实命中点、当前装饰姿态和Info → 地址对应屋顶Entity → 同World的Roof/TriggerVolume Query → 原四元数完整多项式与投影 → 原rank宽度与分段偏移 → 当前高度的真实屋顶截面 → 矩形最近边/边长或圆周长 → UV一次回绕 → 原网格UV到世界点；原函数明确允许UV无解时使用装饰旋转后的本地偏移。该fallback按原指令恢复，不是新增零点近似。

候选距离上限保持100，严格小于更新；三联件中心仍绘制但不可选。普通、中心、选中球分别为0.2、0.05、0.35，动画0.1秒，沿用原`temp_sphere`资产和`outline_split_`名字。名字仍按原part/Vec3与DecoratorId格式化，没有额外mesh/roof盐。只有subtype2/8返回可拆分候选；其它类型仍保留原显示副作用并返回None。rank0不进入部件循环，不能把`dst_as_roof`检查提前。

当前拖出链是：required原Info/派生subtype → subtype2原宽度表或subtype8真实碰撞bounds → 两侧残留组 → 首组原ID change、次组瞬时新ID place → 被拖动原子件新ID place → 返回残留ID数组、新ID、完整DecoratorDst。返回的40B是目的地，不能误作Transform。移动主系统随后从真实RoofTriggerVolume解析该目的地；本函数不另写缓存。

所有操作复用原共享apply、真实碰撞归档资源及DeferredDecoratorEditHistory。新组保留原额外载荷和seed；偏移只回绕一次，不使用`rem_euclid`。竖直偏移在原FracturedPart中存在，但原roof闭包只消费X分量，不能擅自给V补自创移动算法。预览ID通过借用真实基数的`TransientDecoratorIdGen<'_>`分配；不复制ID基数后reserve回填。

显示入口借用 `(hit, info, transform, id, subtype, address, stream, PublicWalls, Query<Roof>, Query<RoofTriggerVolume>)`，返回`Option<usize>`。拖出入口借用 `(part, storage, address, id, transform, derived, transient_ids, live_archivist, optional_deferred_history, events, archival_resources, state, roof, demo)`，返回`RoofSplitResult { remaining_ids, moving_id, destination }`。`demo`由主系统既有真实DevOverride提供，不新增资源或私有影子状态。

## 必要共享事件修复

原apply在`141276e61`保存R8，在`1412772d7/2da`把其完整16B复制到事件`+70`。源地址来自op union，不能把原R8解释为StorageAddr。屋顶拆分调用处`14127c094`明确写这个独立union的`+0c=2`，XYZ此时不活跃。

经中央授权，`DecoratorChangePatch`增加`event_position_flag`，rotation保持0；`from_change`把位置和flag初始化到已有`op.extra[..16]`，`from_change_with_event_data`可覆盖原定义的16B供wall split复用。typed change writer读取这个唯一owner复制事件`70..80`，没有新增队列或magic哨兵。None位置的非活动XYZ和padding规范化为零，不宣称与原未初始化字节逐byte相等。原三个音频consumer均明确跳过状态2，避免拆分事件被旧writer误标为活动零点。

## 本轮经验

1. 从caller读取返回值结构，不依据40B大小猜Transform；本例真实返回DecoratorDst。
2. 原八参ABI与现代七参API顺序不能混用。必须追寄存器到writer：独立position/state16B与sourceAddr是两条数据链。
3. 原子件里placement flag和rank都等于1，足以掩盖字段错位。加入subtype8/rank4后可区分原place `+5c`标志和`+5e`rank；没有依据共享短桩的alias名字推业务语义。
4. NaN差异先保存严格失败，再明确架构边界。有限数值必须保持逐位，不能用近似比较把运算分组问题一起掩盖。
5. rank0反例能发现检查被错误提前。原循环内变体读取不应为代码整洁移到循环外。
6. 复用已验证的截面和瞬时ID owner，保持标准Rust借用和两元素栈存储；查询不克隆屋顶、碰撞世界或造第二套资产表。
