# 桌面版优先开发计划

> v0.1 · 2026-10-08 · 当前执行基线
>
> 用户决定先开发桌面版。以当前 Windows 环境为首个开发/测试平台；不是承诺已经支持 macOS/Linux，也不包含 Steam 上架。Android/iOS 与触摸作为后续移植，不取消纯核心的可移植边界。

## 1. 首版目标与边界

做一个真正可以用鼠标创作、关闭后继续编辑的桌面应用，而不是只展示六栋建筑。保留 1–4 层、自动立面、三种屋顶、规则退台、道路自动门、撤销/重做、保存/载入与拍照。暂不做室内、宠物、手柄、联网或商店集成。

桌面阶段全部核心操作提供可点击 UI；快捷键可以以后增强，但不能成为唯一入口。先支持窗口调整、鼠标、滚轮、文字输入与本地文件；高 DPI、失焦、窗口外松开、最小化和恢复必须进入验收。

当前只实现模块基础、比例实验场及第一步镜头控制；下面的建造、拾取、动画、保存和完整美术仍是待开发。

## 2. 开发顺序与关口

| 阶段 | 实施内容 | 完成门槛 | 当前状态 |
|---|---|---|---|
| D0 基础 | 领域/历史/异步任务、基础 Mesh、比例场 | 测试可运行，窗口能呈现生成结果 | 基础完成，非完整游戏 |
| D1 镜头与选择 | 右键旋转、滚轮缩放、按钮镜头入口、相机工具左键平移、建筑拾取/选中轮廓、统一鼠标事务所有权 | UI 不穿透；镜头与编辑互斥；失焦/窗口外释放能取消 | 旋转/缩放/镜头按钮已接入；平移、拾取与统一工具仲裁待做 |
| D2 自由建造与编辑 | 左键画矩形、候选预览、移动/尺寸/高度/旋转控制点、体块选择与承托、删除、屋顶/样式控件 | 一拖只记一步；取消不入历史；失败可见；撤销恢复同一对象 | 待开发 |
| D3 连续变化 | current/target、稳定 PartKey 匹配、参数/拓扑分治、动画中编辑与撤销 | 持续反向拖动、目标重定向、屋顶切换无空帧/旧结果闪回；拾取跟可见画面一致 | 数值原语已有，画面接入待做 |
| D4 场景关系 | 墙线、道路、自动门、手工门窗覆盖/休眠、局部关联失效 | 道路进出生成/恢复开口；只重建相关对象；旧依赖任务拒绝 | 待开发 |
| D5 本地作品 | 版本化 DTO、ID 分配、原子写入/备份、作品库、命名、关闭保存与 PNG 导出 | 重启继续编辑；写失败不丢旧档、不误报已保存；切换作品拒绝旧任务 | 待开发；离屏测试截图不是玩家拍照功能 |
| D6 美术与桌面交付 | B0–B5 资产接入、音频、画质档、资源回收/性能、高 DPI 与窗口回归、可分发 Windows 包 | 素材来源与预算明确；干净机器可运行；场景与回归报告完整 | 制作合同与 planned 清单已有，正式资产/发行包待做 |

D3 不拖到最后：默认小屋在 D2 可操作后立即验证连续变化。道路和存档可以提前做纯核心测试，但必须按集成关口验收，不能以只有类型/按钮代替完成。

## 3. 当前可运行的鼠标镜头

```powershell
cd D:\game\tiny-garden
cargo run -p garden-presentation --features desktop --bin showcase --locked
```

- 右键从场景区域开始拖动：围绕庭院旋转；越过 UI 时保持该拖动的所有权。
- 滚轮：按距离比例缩放，近远与俯仰均有限制，不能翻到地下。
- UI 面板上开始的右键拖动不启动镜头；面板上的滚轮不缩放场景。
- 失焦或离开窗口取消捕获；回来时必须重新按下，不能复活旧拖动。左键操作期间不处理鼠标镜头运动。
- View / Tilt / Zoom / Reset view 按钮提供镜头入口，不要求键盘。

接口在 `garden-presentation::camera`：OrbitCamera 只保存显示姿态；BlocksWorldInput 配合 RelativeCursorPosition 标记整个工具面板。它不修改 Building/Editor，不把摄像机状态写成建筑命令。

这只是单窗口比例场的镜头适配。D1/D2 要将相机、工具、UI 消费统一到指针事务路由，补上平移和编辑取消；当前组件不能被当作完整编辑输入系统。新增移动端只替换输入适配，不把触点判断塞入领域。

当前[桌面窗口布局截图](../art-source/reference/desktop-camera-v1.png)来自实际离屏 GPU 渲染；不是最终美术，也不替代真实鼠标操作验收。

## 4. 美术如何随桌面优先调整

继续执行[美术资产制作计划](美术资产制作计划.md)，但首轮引擎评审与验收使用 Windows 窗口，手机测量后移，不作为 B1 小屋样片的阻塞条件。程序化主体、固定角/重复中段、米制 UV 与共享材质保持不变。

不因桌面优先就取消预算或立即做高模：先沿用紧凑资产和可降级规则，等桌面真实测量后再调细节密度。先完成石/木/瓦 + 一个可适配窗，不同时精修 26 个 planned 模型。触摸热区、安全区域、Android 纹理压缩、后台生命周期在移植阶段另设验收。

## 5. 验证和排期原则

本轮自动检查重点：镜头初始视图不变、近远/俯仰限制、非法输入、UI 开始拖动不穿透、场景拖动跨 UI 保持所有权、失焦不自动续接、镜头按钮与复位。静态离屏截图只验证呈现与 UI 布局，不代替真实鼠标/操作系统窗口事件测试。

后续桌面至少记录：窗口大小与 DPI、CPU/GPU/驱动、构建模式、场景规模、CPU/GPU 帧时间、局部重建 p95、上传预算与峰值内存。60 FPS 是起始目标，不是已验证承诺；设定参考设备和场景后再冻结性能门槛。

原 Android 全 P0 的 20–29 周与人日估算保留作历史参考，不直接充当桌面交付日期，也不按“少做手机”机械扣减。完成 D1/D2 后，用实际任务速度、美术与设备测量重新估算桌面剩余工作。

桌面闭环通过后再启动移动移植：触摸/双指仲裁 → 工作台适配 → 生命周期/私有文件与图片输出 → NDK/APK → 真机性能。保留原 FR 编号；FR-24 桌面鼠标先验收，触摸随后单独验收，两者不能互相代替。
