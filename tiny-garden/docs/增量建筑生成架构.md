# 增量建筑生成与渐进展示架构

状态：方案 1–4 已接入桌面运行路径（2026-10-09）。本文保留设计约束；实际类型、测试和测量见末节与[优化实现与验收](优化实现与验收.md)。既有线程池隔离不计为本轮新增功能。

## 1. 核心约束

画面仍逐帧绘制。增量化针对编辑后的布局计算、几何生成、上传和资源替换，而不是试图只重绘屏幕上的某个像素区域。

当前已做到「只处理被编辑建筑，不扫描或重建整个世界」。新的目标是继续做到「只处理该建筑内受影响的部件」，并让无关部分保留原资源和展示状态。首次加载、缓存失效或所有相关部分确实变化时允许完整构建；不能为了形式上的局部更新牺牲正确性。

四条方案的落地顺序调整为：先建设方案 4 的部件/差量基础，再接方案 1 的反馈和过渡，方案 2 的后台准备，方案 3 的最新目标优先。方案 4 是结构基础，不是最后才加的一项优化。

## 2. 三种粒度分离

| 粒度 | 用途 | 约束 |
|---|---|---|
| 语义部件 | 判断是否变化、缓存、动画匹配 | 使用稳定身份；不是 GPU draw call 或必须独立的 Entity |
| 几何/上传分块 | 局部重建与资源更新 | 起步按体块、立面/楼层、材质组合形成有界分块；不要按三角形分块 |
| 一致性组 | 保证换图时结构正确 | 相互依赖的墙洞和门窗一起切换；独立装饰可以后续补齐 |

固定窗、门等模板继续复用。实例化与局部合批按测量演进，不为每扇窗、每块砖创建独立绘制对象。分块会改变当前「最多五批次/建筑」的实现预算，实施时必须显式更新预算和测试，不能假定拆分没有渲染成本。

## 3. 身份、输入与差量

以下是设计时的类型候选；实际采用 PartInput / GeometryKey / PreparedBuilding / PreparedBatch，完整目标共享未变缓冲，避免裸差量的展示基准错误。PartSnapshot / BuildPatch 没有额外创建空壳接口：

- `PartId`：覆盖墙面/楼层段、屋顶、露台、门、窗、烟囱等种类；已有 `PartKey` 继续用于窗的语义匹配。位置、尺寸、版本不能进入身份。同一位置的窗变成门时须有明确的种类替换语义。
- `GeometryKey`：描述部件局部几何的生成输入，包括尺寸、开口、样式/模板和规则版本；与 PartId 分开。平移/旋转不应使局部几何缓存失效。
- `PartSnapshot`：不可变的语义部件输入、局部变换和依赖信息；CPU 核心不保存 Bevy Handle。
- `BuildPatch`：包括新增、几何替换、仅变换、仅材质变化和删除；未变化部分不产生更新操作。包含基准展示版本和目标 JobTicket，不能把差量应用到错误的旧版本。
- `PreparedChunk`：后台完成几何验证及必要的法线/切线数据准备；GPU 资源句柄归表现层管理。

缓存键不能只用 PartId：同一窗的宽度或模板变化后不能复用错误网格。规则/模板版本变化也必须失效。浮点生成输入先使用经过领域验证的明确值，不擅自用容差掩盖真实尺寸变化。

## 4. 依赖驱动的失效

| 操作 | 通常需要变化的部分 | 通常可复用的部分 |
|---|---|---|
| 移动/旋转整栋 | 根变换、拾取世界变换；存在道路等关系时另算关联影响 | 当前无外部关系时全部局部几何 |
| 改屋顶类型 | 屋顶、烟囱适配、相关檐口 | 无其他规则影响时的墙面和门窗 |
| 改材质/主题 | 材质绑定；主题比例/模板变化时另失效几何 | 纯材质变化下的结构几何 |
| 改某体块高度 | 墙面、开口/窗位、屋顶位置、上方体块的基底位置 | 参数未变的模板几何；仅位置改变的附件可只更新变换 |
| 增删上层体块 | 支撑块屋顶/露台、对应上层和关联层级 | 没有依赖关系的其他体块 |
| 改宽度/进深 | 相应立面、窗格布局、屋顶及支撑关系 | 逐项判断，不承诺只改一面墙 |

特别注意当前规则：`story_height = height / stories`，因此总高度变化可能使所有窗的高度位置改变；窗格间距变化也可能改变已有窗位置。不能简单把「增高」实现为只补最顶层，更不能整体拉伸窗门。需要从实际输入差异推导失效集合。

门的位置与开口、屋顶与上层支撑、烟囱与坡面之间都有依赖，必须显式传递。门洞结构和门附件使用同一份解析输入，保持现有同源生成约束。

## 5. 渐进计算和一致性发布

流程：权威命令提交 → 立即建立待展示目标/反馈 → 计算受影响部分 → 分批准备与上传 → 一致性组发布 → 独立细节补齐/过渡。

「渐进」不等于任意部件算好就立刻贴上去。旧墙洞不能配新窗，新屋顶不能与仍在旧高度的墙顶错位。

- 一个一致性组可跨多个计算/上传批次准备，准备期间保留旧有效组；达到可绘制条件后协调切换。
- 主世界换网格不代表渲染世界准备完成。表现层单独确认必要的渲染资源/管线就绪，不把 GPU 等待塞进领域提交。
- 每帧预算包含上传字节、几何/实例数量和资源创建成本，而不只统计「最多两栋」。为单个超大分块设上限或进一步拆分，避免一个分块耗尽整帧。
- 更新优先保证建筑主体和开口一致；独立装饰可以后补，不能通过临时封住原来的门洞来假装完成。
- 资源缓存和待发布组有容量与回收规则；失败、取消、删除、撤销或换作品时释放未使用资源，保留旧有效展示。

## 6. 预览和动画

方案 1 使用独立展示状态：current、target 和待生成票据。预览不是新领域模型或完整生成结果，不污染撤销历史，也不冒充正式精确拾取数据。

先提供目标高度轮廓/简化主体与明确状态，目标是在下一个可呈现帧给出反馈。若 GPU 本身积压，预览也不能绕过它；不要承诺 CPU 有反馈就一定显示即时。

已有 `SmoothValue` 可用于数值连续重定向，但它尚未接入画面，且不是速度连续的弹簧。匹配的部件从当前展示值续接；新增/删除部件单独过渡，不能对不同拓扑的两套网格硬插值。动画、布局差量和缓存身份必须使用一致的语义匹配。

拾取须遵循当前可见正式几何；独立预览有独立交互规则。真正接入可见形变时，须同步拾取模型，不能保留旧 CPU 网格去拾取已经变形的画面。

## 7. 任务调度与后台准备

方案 3：命令立即提交，历史按命令策略保留；合并的是生成目标，而不是偷偷吞掉用户编辑。每栋最多一个在途生成任务，并保留一个最新待生成目标，多栋之间仍需公平调度。

旧任务在布局解析、结构几何、装饰组装和切线准备等边界检查取消。取消是协作式，不宣称 drop 能强制终止 CPU 运算。保留 session/规则/对象版本校验；部分结果同样受 JobTicket 保护。

方案 2：在 CPU 工作线程准备局部网格与切线。若需要切线库，保持纯核心无 Bevy/GPU 依赖，不把 Assets 或渲染句柄传进生成任务。主线程保留必要的资源安装职责。开发优化级别按真实测量选择，不盲目增加线程。

## 8. 实施阶段与验收

1. **身份与差量基础**：建立 PartId、输入键、部件快照与纯函数差量；先覆盖移动、屋顶变化、增高。现有整栋路径作为对照，不立即删除。
2. **真正局部更新**：缓存并复用未变分块、处理仅变换/材质更新；增量结果与完整生成在几何/布局语义上等价。GPU 资源按一致性组发布，统计复用率、生成顶点和上传字节。
3. **后台准备与调度**：切线准备移出主线程、同屋最新目标优先、协作取消与预算回收。测试连续增高、撤销、新旧结果交错及删除。
4. **即时反馈与连续衔接**：目标预览、主体与细节协调更新、动画重定向，验证拾取和显示一致。
5. **真实窗口验收**：记录输入→反馈、计算、上传、可绘制与呈现相关时间；看样本分布而不只平均值，并检查绘制批次、峰值内存和长时间连续编辑。

关键回归：移动不重建局部几何（当前无外部关系）；屋顶变化保留未变墙面资源；高度变化正确处理窗位和支撑链；多帧发布无洞口错配；差量基准错误不被应用；过期片段不混入最新组；增量与完整构建等价；资源回收有界；独立建筑不会被牵连重建。

当前的领域约束、命令入口和六 crate 依赖方向保持不变。逐步替换粗粒度派生数据，而不是在一次改动中重新搭建全部游戏架构。

## 9. 当前实现与边界

- `generation/incremental.rs`：建筑根内作用域的 PartId、BatchId、精确 GeometryKey、局部偏移、CPU 缓冲共享、协作取消及 reconcile。墙按面、屋顶独立、门独立、窗按面/楼层/每组最多 8 扇分块；不创建逐窗实体。
- `presentation/building_kit.rs`：真实 Blender 模板的增量路径，规则和模板 v4 进入 key；原整栋编译保留作对照。默认纯结构路径也按墙面/屋顶增量，第三方整栋编译器保留兼容 fallback。
- `bevy-adapter`：每栋一个在途任务、一个最新 pending；未确认取消不释放槽位。缓存每栋最新成功 CPU 快照，删除/换作品清理。`prepare.rs` 后台使用与 Bevy 相同的 MikkTSpace/切线手性；四个纯核心仍无引擎依赖。
- `renderer.rs`：仅上传改变的缓冲，仅偏移变化复用 GPU Handle；每帧默认 512 KiB/8 批次，建筑间轮转。确认 RenderMesh 就绪，关联墙洞/门窗/屋顶协调切换。完整共享目标与当前驻留资源比较，跳过中间票据不导致错基准拼接。
- `PendingTargets`：有效命令提交当帧提供目标；选中建筑显示青色目标轮廓/中文进度。生成失败保留原画面、目标变红；无效命令无假预览。
- 动画：根移动/旋转从当前值连续重定向；变化部件约 160ms 整组淡化，未变部件不动。零透明度实例预热过渡管线，旧模型保持不透明直到可见实例管线就绪。只判断主相机可见性，不把阴影视角误当镜头内可见；镜头外直接完成发布，避免等待不排队的管线。首次场景载入无全场建造过渡。
- 拾取：使用局部网格、偏移和实际根变换；淡化前半段旧完整姿态、后半段新完整姿态。透明叠加有两个可见姿态，交互选主导姿态，不混合两套三角形；目标线框不进入正式拾取。

当前以一栋建筑作为保守发布一致性组；计算/上传已经部件级、跨帧、有缓存，不重新合并整栋网格。尚未做任意依赖岛独立发布、逐顶点形变、C1 弹簧、GPU 实例化/LOD、大场景 draw-call 压力或真实窗口呈现延迟统计。布局 compile 仍完整解析被改的单栋（最多 3 体块），不是全场景解析；重点消除昂贵的重复网格/切线/上传。

过渡实现拆入 `renderer/transitions.rs`。已开始的短过渡保持连续；尚在等管线、未开始的旧目标遇到新命令时撤回暂存/零透明度实例，恢复原驻留资源，让最新目标接续，不阻塞在过时预热后面。

结构 UV 使用体块局部锚定：米制比例/立面切片相位保持，移动上层时纹理跟随体块，不随世界高度漂移。几何对照允许局部加偏移的 f32 舍入差异，不声称旧世界坐标 UV 相位逐位相同；Blender 模板 UV 不变。

局部化将稳态批次从整栋最多 5 批变为材质分块，本机七屋截图 197 批；这不是 GPU draw call 测量。CPU 收益不能替代 GPU、填充率与阴影预算验收，见[优化实现与验收](优化实现与验收.md)。
