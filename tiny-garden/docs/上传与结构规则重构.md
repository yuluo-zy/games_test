# 上传流程与结构规则重构

> 2026-10-10 · 保留六个 crate 的职责与依赖方向；本轮重构上传基础和结构解析。

## 问题与设计意图

房屋与墙路各自管理上传队列、预算准入、GPU 网格就绪和取消回收，超大批次处理不一致。预览、正式网格和烟囱定位也分别计算承托高度、有效屋顶、朝向和坡高，容易在扩展时产生行为偏差。

本轮把通用流程集中到共享实现，同时保留各类型的业务规则和发布策略。没有新增 crate，也没有把权威领域数据或编辑票据塞进公共上传层。

## 上传基础

`crates/presentation/src/upload.rs` 提供如下合同：

| 组件 | 职责 |
|---|---|
| `UploadSource` | 类型提供不可变批次快照和本地索引；公共层通过静态分派访问 |
| `UploadStage<K>` | 共用待上传队列、复用句柄、新资源所有权、预算推进、就绪检查及取消回收 |
| `UploadContext` | 公共网格创建入口，共享当帧资源和用量账本 |
| `UploadBudget / UploadLedger` | 所有类型共用每帧字节及批次数限制，在安装前统一重置 |
| `MeshReadiness` | 连接实际 RenderMesh 和材质管线就绪；一致性组一次加锁检查网格或绘制状态 |

房屋使用 `PreparedBuilding` 的批次来源实现，墙路通过 `StrokeUploadSource` 提供复合索引。上传队列只在成功上传后前进。超预算批次只允许作为当帧第一个批次，计入类型的超大批次统计，避免小预算造成永久等待；这意味着字节预算对不可再拆分的批次是软上限。

暂存只拥有新上传句柄，复用句柄归已发布的驻留结构持有。目标失效时只回收新资源，避免删除仍可见的旧画面。正式发布后，各类型接管驻留和回收责任。房屋安装仍先于墙路安装，公共账本防止两者分别获得一份预算；本轮未新增跨类型公平调度器。

各类型继续负责：
- 目标是否仍有效、何时创建或移除实体；
- 房屋位姿平滑与淡化，墙路整组预热与替换；
- 可见拾取数据、类型统计和发布通知。

新增展示类型时实现自己的 `UploadSource` 和安装策略，复用公共阶段；不得另写一套预算或 GPU 上传流程。

## 结构数据与按类型运行规则

`crates/generation/src/structure.rs` 提供无引擎的结构合同：

| 组件 | 职责 |
|---|---|
| `BuildingStructure / BlockStructure` | 承托高度、体块尺寸、层数、实际屋顶和退台区域 |
| `RoofInput / RoofStructure` | 完整几何配置，以及统一的横纵向范围、坡高和屋脊端点 |
| `StructureRule` | 每种规则声明自己的输入、输出、输入等价判定及解析算法 |
| `BuildingRule / RoofRule` | 体块关系规则，以及按平顶、双坡、四坡类型分支运行的屋顶规则 |
| `RuleCache<R>` | 所有规则类型共享的单快照缓存；精确比较，命中时复用解析结果 |

结构结果不含世界放置。建筑规则比较体块数据，平移与旋转复用局部结构。屋顶缓存完整比较尺寸、类型和几何配置，配置变化不会错误复用旧坡高。规则实例在缓存创建后固定；以后增加可变规则配置时，必须将其纳入输入或重新创建缓存。

正式布局消费体块结构并扩展门窗；正式屋顶网格与全量/增量烟囱定位消费统一屋顶数据。预览使用相同规则，但仍采用低成本棱柱/锥体拓扑，不代表完整正式屋顶。预览池保留一个建筑快照、最多三个屋顶快照，并复用形状缓冲容量，避免静止预览逐帧解析和分配。

公共缓存只保留最新输入，没有无界参数历史。它适用于连续复用的消费者；持续变化时需要重新解析和保存输入，不能假定缓存总会更快。既有部件增量网格缓存继续负责网格复用，结构缓存不替代它。

## 验证与性能范围

回归覆盖：不同类型共享极小上传预算仍能完成安装、取消暂存保留复用网格、实际渲染就绪检查、屋顶类型/配置失效、世界放置复用局部结构，以及预览与公共规则参数一致。既有增量与全量网格对照、资源回收和过渡回归继续运行。

CPU 结构基准命令：

```powershell
cargo run -p garden-generation --example structure_benchmark --release --locked
```

本机 release 构建，3 个体块、100,000 次调用的一次测量：完整结构解析 1043.0 ns/次，缓存命中 26.3 ns/次，持续变化导致缓存失效 1285.8 ns/次。测量说明复用场景收益及失效时的额外成本；不代表整个游戏提速比例、GPU 帧率或窗口交互延迟，其他设备应重新测量。
