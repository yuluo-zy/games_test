# 墙路自动重构实现与验收

> 本页保留第一阶段墙路切片的历史。2026-10-10 后续已接入三态、道路语义图、建筑门、连窗与地形地基，并统一显示交接；当前状态见[上下文系统实现与验收](上下文系统实现与验收.md)。

桌面版现在支持在草坪上画独立砖墙和道路。玩家画路横穿墙中段时，系统重新构造墙砖和拱砖；删除或移开道路，墙体恢复。道路之间采用同一影响场生成路面，交叠处不会叠放两层面片。这是上下文自动重构的第一块可玩切片，不是 Tiny Glade 全部玩法的复刻。

## 操作与范围

选择「画墙」或「画路」，按住左键拖动，松开提交一笔。绘制时显示青色轨迹和墙高线；红色表示候选数据不合法。选择「墙路编辑」，点击可见墙路后拖动整体移动，或者用墙高、宽度、删除按钮编辑。房屋与墙路共用撤销和重做；取消拖动不会记入历史。

墙路只作用于平面草坪和独立墙体，不会改变现有房屋门窗。当前不支持道路拉高变篱笆或围墙、窗户合并、道路导航图、地形、存档及触摸适配。材料沿用项目现有石墙和灰泥材料，砖块不是导入的固定整墙模型。

每场景最多32笔，每笔2至128点，总长不超过60米；宽度0.25至3米，墙高0.8至5米。笔画及宽度安全边界必须落在庭院内。绘制采样间距通常为0.2米，收笔允许0.04米；超过采样上限拒绝提交，不让拖动缓冲无限增长。

## 模块和数据流

| 层 | 文件 | 职责 |
|---|---|---|
| 领域 | `crates/domain/src/strokes.rs` | `StrokeId`、墙路类型、轨迹、宽高、合法性和包围范围 |
| 应用 | `crates/application/src/strokes.rs` | 创建、替换、删除，乐观版本检查，共享历史，删除编号墓碑 |
| 生成 | `crates/generation/src/strokes.rs` | 弧长采样、距离影响场、穿墙关系、墙砖和拱砖、统一路面 |
| 引擎适配 | `crates/bevy-adapter/src/strokes.rs` | 有界后台任务、取消旧版本、依赖快照和网格缓存、后台切线 |
| 表现 | `crates/presentation/src/strokes.rs` | 鼠标射线、预览线、实际网格拾取、上传、安装与资源回收 |

输入先形成候选笔画，松开后才提交领域命令。领域快照是权威数据，砖块、拱口、路面和引擎句柄均为派生结果。路面派生组保留编号0，不能作为玩家笔画编号；点击统一路面时根据原始轨迹选择笔画。

一次撤销只恢复一笔编辑，而不是分别撤销道路和自动拱口。墙路版本随有效提交单调前进；撤销也产生新版本，旧任务无法覆盖新状态。场景替换同时清除墙路和撤销历史。

## 生成算法

### 轨迹和砖块

轨迹累计各线段长度，通过二分查找按弧长采样位置和切向。墙体以约0.48米横向间距、0.26米层高排砖，奇偶行错缝；末端裁短，厚度变化由行列哈希决定，相同输入生成相同结果。弧长排列避免拐弯处按世界坐标等间隔摆放造成疏密变化。

每96块以内合并成一个网格批次，不为每块砖创建实体。急折角、自交和转角砖咬合没有专项修复，可能出现穿插或缝隙；本轮不能将任意曲线生成称为生产级拓扑求解。

### 道路影响场和统一路面

点到折线各段的最近距离，经道路半宽转换为影响强度。多条道路取最大值，形成同一覆盖区域。路面按0.25米网格采样，每个被覆盖单元只生成一个四边形，因此相交道路没有重复面。

这是一片统一的路面几何，不是可导航的连接图。边缘具有网格量化，靠得很近但未覆盖同一单元的道路不会自动吸附；后续可以将这个接口替换为轮廓布尔并集和三角剖分。

### 穿墙关系和拱口

先用扩张包围框筛选墙附近的道路，再沿墙每约0.08米采样。只有横穿局部墙线、与墙切向夹角足够大的道路线段才形成开口，平行贴墙道路不误开门。连续受影响区间扩张后合并，记录道路来源编号。

本轮只生成墙中段的拱口，开口宽度不超过4米，两端距墙端至少0.15米。过宽或碰到墙端的情况保持墙体，不生成没有承托的拱；这是原型约束，不是原版行为。拱高取墙高的70%，上限2.2米，以半椭圆描述轮廓。

墙砖根据拱轮廓保守截短或移除，再沿拱线排列24段拱砖。开口是实际三角形几何变化，低处射线能够穿过，不依赖片元丢弃模拟洞。砖底为分段截断，拱口边缘仍有台阶感，尚未做精确曲面裁剪。游戏没有新增物理碰撞系统；这里验证的是编辑拾取一致性。

## 性能与安装

生成和切线计算运行在既有专用线程池内。墙路最多一个在途任务，新编辑取消旧任务，后续只启动最新快照；旧结果必须匹配当前版本才可发布。

缓存键包含墙笔画以及影响它的道路快照。道路变化只重新生成相关墙，远处墙复用同一 `Arc` 网格和 GPU 句柄。相关墙仍整墙重新生成，不是墙内按开口局部更新；统一路面在任何道路变化时整体重建。当前32笔上限下这是明确的性能边界，不能据此推断万级场景性能。

新墙路与房屋共享每帧512 KiB、8批次的默认上传预算。上传期间保留旧完整画面，等待 GPU 网格和可见材质管线准备，再发布新派生组和拾取网格。取消过时安装、删除和场景替换会清理对应网格资产和实体。

墙路尚未复用房屋的160毫秒整组淡化。新实体在材质预热时可见，旧实体到交接时才删除，可能短暂重叠；没有把这部分描述成无缝动画。下一步应抽出通用派生组交接组件，统一房屋和墙路的预热、淡化和拾取切换。

## 验收方式

自动测试覆盖弧长采样、重复道路并集、横穿与平行规则、取消生成、局部缓存、统一历史、过时版本拒绝、删除恢复和场景清空。桌面交互测试用实际屏幕投影和指针帧绘制墙路，验证真实开口拾取、无关墙 GPU 句柄复用、上传预算、按钮增高、取消和无效收笔。

2026年10月10日本机验证：113项工作区测试通过（应用25、适配12、领域7、生成12、几何2、表现55）；Clippy 全目标全功能零警告、格式和依赖边界检查通过。Intel UHD 630 Vulkan 两次离屏截图均退出0，已显示道路与真实拱口，最终参考图为 `art-source/reference/wall-road-review-final-20261010.png`。运行时仍有 ICU4X 中文分词模型警告，但中文字体正常显示；稳定状态文字已避免反复赋值和排版。

在项目根目录运行：

```powershell
cargo test --workspace --all-targets --all-features --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
./scripts/check-boundaries.ps1
cargo run -p garden-presentation --features desktop --locked -- --wall-review D:\game\tiny-garden\art-source\reference\new-wall-review.png
```

`--wall-review` 走真实命令、后台生成和 GPU 渲染链路，依次创建墙、创建穿墙道路、删除道路和撤销删除，最后截取恢复的拱口。它不是操作系统鼠标回放；真实窗口失焦、全部 DPI 和触摸验收仍需单独执行。截图路径必须是新文件。

## 后续扩展

墙路相关文件提供了独立领域输入和纯 CPU 生成接口，后续不需要让 UI 直接修改网格。通用系统下一步先把穿墙区间提取成稳定关系结果，再让门、拱、篱笆连接等规则消费它；加入空间索引和局部道路轮廓重建后，再按稳定部件细化相关墙缓存。窗户合并和路篱笆围墙转换需独立领域规则，不能用材质替换冒充结构重构。

概念参考作者早期公开项目 [country-slice](https://github.com/anopara/country-slice)。本实现独立编写，未引入其 OpenGL 渲染器或源码；采用后台 CPU 实际开孔，而不是移植早期片元丢弃和计算着色器流水线。
