# 编辑延迟优化 1–4：实现与验收

2026-10-09。仅本地修改，未提交/推送。范围为现有桌面建筑编辑，不是完整 P0 或移动端性能验收。

## 四项交付

| 方案 | 实际实现 | 回归依据 |
|---|---|---|
| 1 即时反馈与衔接 | 提交当帧建立 PendingTargets；目标轮廓/中文进度；根变换平滑重定向；拓扑变化整组 160ms 淡化，首次载入无全场过渡 | 无效命令无假目标；连续增高/撤销收敛；拾取随主导完整姿态切换 |
| 2 后台准备/开发优化 | 仅失效部分的几何、验证、切线；MikkTSpace 在生成池内运行；generation opt=2、presentation/adapter opt=1，其他核心 opt=0，外部依赖 opt=3 | 后台切线与 Bevy 一致；上传系统不生成切线；核心依赖门禁通过 |
| 3 最新目标优先 | 每栋一个在途任务和最新 pending；旧任务在阶段/部件/附件/切线批次边界取消，确认取消才释放槽位；忙碌对象不挡住其他对象 | 阻塞旧任务期间连续 10 次编辑仍只有一个任务，11 条历史保留，随后只派发最终目标 |
| 4 真正增量化 | 稳定身份 + 精确输入 key；CPU 缓冲共享、仅变换复用 GPU 网格；默认每帧 512 KiB/8 批次；跨帧准备，一致性组切换 | 移动零新顶点/零上传；屋顶修改保留墙窗 Handle；支撑高度传播偏移；暂存期间旧画面完整；删除/换场景回收资源 |

既有独立 GenerationPool 与外部依赖优化不计本轮新增。新增的是部件缓存、后台切线、取消/串行槽位、字节预算、就绪确认和实际预览/动画。

## 数据流与代码

```text
Editor.execute（校验、权威意图、Undo）
 → PendingTargets（本帧反馈）
 → 最新目标/取消调度 → 单栋布局 → 部件输入/key 对照
 → 复用旧缓冲 + 失效网格/后台切线
 → 版本校验 → 完整共享目标
 → 改变分块分帧安装 → RenderMesh/可见过渡管线就绪
 → 一致性组切换/过渡 → 正式拾取同步 → 旧资源回收
```

入口：`generation/src/incremental.rs`、`presentation/src/building_kit.rs::compile_incremental`、`bevy-adapter/src/{lib,prepare}.rs`、`presentation/src/{renderer,editor,picking}.rs`（均位于 crates 下）。

PartId 以建筑根为作用域，不含尺寸/位置；GeometryKey 捕获局部输入/比例/规则和模板版本；BatchId 为部件+材质。缓存每栋最新成功快照，不无限保存历史尺寸；旧展示、短过渡、暂存目标共享必要引用。纯核心不保存 GPU 句柄。

发布完整目标（共享未变缓冲），不是裸差量补丁；渲染器跳过中间版本仍可比较当前资源，避免错基准拼接。关联洞口、门窗和屋顶不跨版本混用。未来道路/依赖岛没有在本轮虚构实现。

## CPU 基准

```powershell
cargo run -p garden-presentation --example incremental_benchmark --features desktop --locked
```

本机 Windows/dev，真实 kit v4，10m 宽房屋，每种场景连续 30 次操作；同一优化编译配置比较整栋/增量。包含布局、网格及切线，不含排队、UI、GPU 上传或窗口呈现。

| 操作 | 整栋 P50 / P95 | 增量 P50 / P95 | 新生成顶点 / 整栋总顶点 |
|---|---|---|---|
| 移动 | 37.710 / 42.757 ms | 0.042 / 0.080 ms | 0 / 906,060 |
| 屋顶交替 | 33.962 / 72.054 ms | 1.002 / 1.547 ms | 18,330 / 891,330 |
| 自动层数增高/回落（6/9/12/15m） | 69.006 / 80.972 ms | 16.226 / 20.183 ms | 268,144 / 1,467,244 |

增高新顶点减少约 81.7%。这些 CPU 样本不是“点击后 16ms 必定看到画面”的承诺；GPU 积压、首次着色器编译、帧预算仍影响呈现。

## 边界与配置

1. 局部化增加绘制批次：旧七屋截图 31 材质批次，新场景 197（还多执行一次增高，不是同场景严格 GPU 对比）。本轮没有证明 GPU 总帧时间改善；大场景仍需实例化、LOD、可见性与质量分档。
2. 512 KiB/8 批次限制主世界网格安装，不是 GPU 时间硬限额。真实 kit 的 100×100m/4 层分块通过默认字节预算测试；第三方整栋 fallback 的过大单块允许独占一次安装，计入 oversized_batches。
3. 当前保守的一建筑发布一致性组可跨帧准备，不是每算好一个碎片立即贴上去。变化部分短时双姿态/透明填充，无关部件保持实体/资源，不重新合并全屋上传。
4. 透明管线预热不阻塞 UI，旧画面保留；确认的是资源/管线可用，不是 GPU 队列执行完或显示器呈现。镜头外直接完成版本切换，避免等不排队的管线。
5. 根变换值连续指数平滑，停止后移除动画组件；已启动的拓扑过渡不中途重开，最新目标可先准备，约 160ms 完成后接续。尚未启动、仍在等待冷管线的旧目标会立即撤回未发布资源，恢复有效驻留，优先接续最新目标；该竞态有回归。不是 C1 弹簧或任意拓扑逐顶点形变。
6. 单栋布局仍完整解析，昂贵的网格/切线/上传按部件增量；未实现道路依赖岛、存档、移动真机或全量美术。

配置：UploadBudget、TransitionSettings。统计：PipelineStats 的取消/重建/复用/顶点；RenderStats 的字节/复用/暂存/过渡批次。
