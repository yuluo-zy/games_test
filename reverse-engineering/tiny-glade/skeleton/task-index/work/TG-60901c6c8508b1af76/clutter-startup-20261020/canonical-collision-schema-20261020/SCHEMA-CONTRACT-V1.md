## Original values and ownership

Native loader closure0 1069B, closure3 833B, load_collision_as_bbx1284B, empty583B, shared insertion942B and four-table insertion996B consistently write one 64-byte DecoratorCollision: a 24-byte Vec of 36-byte Triangle values, one Arc<RaycastMeshData> at +18, and Rectangle3d at +20. Its footprint center/axis are +20/+24 and +28/+2c; dimensions are +30/+34; vertical bottom/top are +38/+3c. Logical safe Rust fields are `triangles: Vec<utils::geometry::Triangle>`, `mesh: Arc<RaycastMeshData>`, `bounds: Rectangle3d`. Do not substitute a bbox-only record or claim Rust layout repr equivalence. This value is Clone, not Copy; cloning copies triangles and shares the same actual RaycastMeshData Arc.

The original four HashMap value types are explicitly PDB bound: map0 collision and map1 interaction store DecoratorCollision directly. Map2 stores DecoratorOutline and map3 stores DecoratorCollisionOutline. Existing four Arc<LegacyDerivedDecoratorInfoRecord> tables are wrong. Replace those actual four fields; no second registry, opening resource table or compatibility geometry map. The original logical key is subtype plus rank, both byte-valued. Its native constructor raw inputs(rank,subtype) return registers(subtype,rank), whereas current safe host `DecoratorLibKey::new(subtype,rank)` already names logical fields. Retain this logical argument order and document variant as rank; bind each caller using its original inputs instead of blindly swapping all callers to raw register order. Empty subtype0x1a is an enum/key sentinel, not an arbitrary replacement for missing assets.

Primary DecoratorOutline payload is independently visible in full2876B display plus both insert bodies: tag0 a String at +8 (clone and string-byte deallocation), tag1 Vec<Vec3> at +8 (12-byte element stride), tag2 radius f32 at +4, tag3 None. Proposed safe names `Mesh(String)`, `Lines(Vec<Vec3>)`, `Sphere(f32)`, `None` denote those observed logical payloads. CollisionOutline has the separately proven Lines(Vec<Vec3>)/Sphere(f32)/None payload. Do not implement displays from this schema packet alone: primary callbacks, true factory and Sphere animation remain their own original-evidence dependencies. A present explicit None variant is different from an absent table key.

## Exact mutation and failure order

`insert_collision_and_interaction_as_same(key, collision, outline, collision_outline)` accepts owned actual values. It clones collision.triangles and its same Arc once; inserts the clone in collision table; moves the original collision into interaction; moves outline into outline; moves collision_outline into collision_outline. Each old replaced value is dropped after its insertion, before proceeding. No cloning a whole Legacy record four times. The native clone allocation and Arc increment appear before the first insert; allocation/refcount failures remain failures, and partial earlier table mutations are observable on a later panic.

`insert(key, collision, interaction, outline, collision_outline)` also explicitly clones the first collision into map0, moves the separate interaction into map1, moves both outline values into maps2/3, and finally drops the original collision after all insertions (140b26572..5a5). Preserve this real clone/drop order; do not silently optimize it into a move or transactional all-table replacement without separate evidence. Rust owned inputs and ordinary HashMap insertion/drop provide panic-safe ownership. This packet does not add a rollback that the original lacks.

`DecoratorCollision::empty()` is not an all-zero shape or zero bbox. Native583B passes center ZERO and dimensions ONE to Rectangle3d::new with zero yaw, creates a real SharedShape cuboid with zero half-extents, identity/zero-translation rigid pose, and an actual shared RaycastMeshData owner with zero-geometry hash; triangles are empty. The existing `RaycastMeshData::new_cuboid_at(Vec3::ZERO,Vec3::ZERO)` supplies the genuine zero cuboid, paired with Rectangle3d::new(Vec3::ZERO,Vec3::ONE,Vec2::X). This actual constructor is native-physics gated in current host. The non-native-physics domain must explicitly remain unavailable; never manufacture a shape-less object and label it genuine. Central must choose a coherent feature/test boundary before source integration; current mac App already enables native-physics. This is a build-capability boundary, not permission to return a fabricated collision.

## Required borrowed API

The two complete getters, 140b26690/352B and 140b267f0/378B, return a pointer into their actual map value on success, with no Arc clone or payload clone. Empty maps and a missing exact key both reach fmt panic; a None enum stored at the key is returned normally. Restore `get_outline(key)->&DecoratorOutline` and `get_collision_outline(key)->&DecoratorCollisionOutline`. Existing `Option<Arc<LegacyRecord>>` results are an incorrect simplification.

For current native business consumers that read the original direct collision HashMap entry, expose one safe host borrowed adapter `collision_record(&self,key:DecoratorLibKey)->&DecoratorCollision` and analogous `interaction_record`. Missing exact keys preserve the required formatted failure. The helper name is a currenthost adaptation; do not falsely attribute that spelling to original author. Bounds users read `record.bounds` directly: width is X, height is top-bottom Y. Neither X/Z legacy dims nor a default box may stand in. This adapter never clones triangles per decorator/frame.

Do not conflate that borrowed record adapter with original `collision_mesh` and `interaction_mesh` methods. Their indexed inline bodies include required HashMap get/unwrap and Arc clone. Their intended output is the actual same owner Arc<RaycastMeshData>, not a cloned Vec/bbox record; finish binding the selected original caller span before implementing those names. Likewise exact original get_collision_bbx_ls/dims_wall_space signatures remain to be bound from their inline users; this schema packet does not assume that current `(Vec3,Vec3)`/Vec2 signatures are original. Required current consumers can use the proven borrowed bounds adapter immediately after a coherent library migration.
