The exact order is:14081d0d7 constructs the iterator over the existing modified-ID set,14081d0e0 calls **len**, d0ec/d0ef checks len==0. An empty modified set skips Public lookup, but a corrupt nonempty modified set with missing Info does not skip Public.

The actual next is also strict: after taking one ID from the modified set, b366 tests the authority map length; empty map branches b36b to b41d unwrap failure. Current Decorators::iter_modified_mut clones IDs into a Vec and uses if-let, so its allocation and stale-ID skip are not the native iterator contract. This package does not modify that foreign helper or its unknown callers.

For the owned nine-parameter system the minimal safe adapter is: after the already-proven mutable Storage guard, split-borrow existing modified_ids and decorators; if modified_ids.is_empty(), continue without Public lookup. Otherwise require the actual PublicWallState first. Then iterate modified_ids in their existing set order and require decorators.get_mut(id).unwrap(), committing each actual Info before advancing. No Vec, map clone, dedup or implicit skip is needed. This preserves both failure precedence (missing Public before missing Info) and the per-ID lookup/iteration; it does not claim O(1) work or measured speed.

Required negative tests: nonempty modified set plus missing Public and missing Info must fail at Public first; nonempty set plus present Public but absent Info must unwrap/fail; empty set plus missing Public must skip successfully. Normal actual IDs retain original per-set order, and original ordinary stores must precede optional subtype/bottom work. This new pack is read-only evidence/design; no source, Cargo/rustc/tests, App/GPU, or benchmark was run.
