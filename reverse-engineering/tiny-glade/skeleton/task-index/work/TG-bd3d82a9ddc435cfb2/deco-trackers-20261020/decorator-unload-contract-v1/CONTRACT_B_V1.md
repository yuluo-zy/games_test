## Real resource/lifetime boundaries

The current sparse take_out_waste clears byte_map/active bits and reversely returns chunks, and try_gpu_flush calls it before uploading dirty data. Merely enqueueing waste is not evidence that active bits or the next draw are already clear. The native remove-resource command is proved, but current removal alone does not prove the BufferHost slot or in-flight GPU resource retired. This requires the actual mesh producer/managed-owner contract, not a new host table or a guessed release of a potentially shared ID. Native dependency destructors are reused, not rewritten here.

## Failure order, source plan and verification

The function is not an all-resources atomic transaction. A later Default/TLS allocation failure happens after the already completed earlier resets, while not-yet-replaced resources retain prior values; EH drops constructed temporaries. The command is queued last, so early failure does not authorize removal or entity destruction. Retain native resource order, use assignment semantics rather than take/default with reordered Drop, and preserve graph/affordance clear semantics. Bevy missing required resources is a system-initialization/configuration failure before this body; do not convert absent mandatory owners to Option and silently consume unload as success.

After07 reviews this contract, root should allocate explicit source scope for the canonical missing resource/consumer owners and the tiny-glade full unload entry/registration. The root window fragment must be reconciled in one coherent final function or retained as an explicitly scoped independent fragment; no duplicated same-owner reset or unordered split should be advertised as the complete9451B order. Do not register a function omitting missing parameters as the whole unload chain.
