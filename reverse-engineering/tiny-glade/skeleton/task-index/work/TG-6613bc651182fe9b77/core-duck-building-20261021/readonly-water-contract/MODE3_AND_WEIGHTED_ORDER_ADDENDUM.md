# 两项算序精化（不改前份freeze）

绑定完整合同SHA d19e369a0c198f98057381e6a331b35792f3f058ed5411171b72f60cf5067e84；这是同一原9331B的算序精化，不扩scope。

1. kind3原140816e8f..eaa：先dx²，另算dy²后加dx²，最后由dz²目的寄存器加前和；因此精确书写是 `dz² + (dy² + dx²)`。主合同该句写成 `(dy²+dx²)+dz²`，有限值相同，但不足以声称NaN payload操作数顺序。实现应按这里对应的原寄存器顺序；不使用另一个Vec3.length_squared求和顺序替代。
2. 共同3D插值140816b4e..b82原先算w0=1-t，分别先乘P0和P1再相加；xy的最终目的寄存器是P1*t，随后加P0*w0；z同样是P1.z*t加w0*P0.z。主合同weighted写法表达了不用差分lerp的业务数值，精确表达应为 `P1*t + P0*(1-t)`，原z0乘的操作数顺序另为w0*P0.z。现安全Vec3值表达与原非有限最终insert失败域应保留，不把普通代数相等泛化成全NaN payload位等价。

这两项均能在既有主asm直接核对；未写source或运行Rust/原程序。
