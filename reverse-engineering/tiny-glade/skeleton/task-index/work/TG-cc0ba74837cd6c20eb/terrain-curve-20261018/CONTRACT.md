# Terrain rock-mask mapped storage correction, original B

Exclusive source owner TG-cc0ba74837cd6c20eb; target B despite the task index's default C label. This is a minimal correction to the current hand-written TerrainRockMaskSsbo descriptor, using the existing AssetSsboLibrary and MappedStorageBuffer APIs. It does not replace either module, the bit sampler, or the renderer. No production or Cargo change was performed by this worker.

The current resource descriptor erroneously treats native0x8000 bytes as0x8000 u32 elements, allocating128KiB rather than32KiB. Its short name also incorrectly includes the Ssbo type suffix. Original mapped constructor0x141620320 allocates0x8000 zero bytes at0x141620390, constructs BufferDesc(byte_size0x8000,usage0x22,memory4) at0x141620415..423, aligns4 at0x14162043e, and passes the exact15-byte name TerrainRockMask at0x141620469..47d. It divides mapped byte length by4 at0x141620513 before returning the typed slice. Initial byte lengths at or above0x8004 are rejected before device calls. The current generic wrapper already implements these contracts correctly once the resource's constants are fixed.

The candidate changes only NAME to TerrainRockMask and BUFFER_LEN to0x2000 u32 words. One actual AssetSsboLibrary regression uses the existing shared MockDevice to check emitted descriptor/name/zero initialization and mapped word count, then verifies the last valid bit remains addressable by the real mask sampler. This is a real constructor-to-consumer check, not an assertion of those two constants alone.

Five independent original constructor executions confirm no-data zero initialization, one-word initial data, full native initial capacity, one-word excess rejection and non-word-sized input rejection. Original allocation/default fill, guards, BufferDesc construction, mapped length conversion and return execute unchanged. The actual graphics create/map APIs are resolved dependency boundaries; they supply a real harness mapping and retain the arguments produced by native instructions. Rejection runs stop at the actual original panic entry. The original B image/PDB identity and bounded byte/source pack are retained; C is not tested.

The current mouse and rock mask typed constructors and CPU consumers exist. The inspected actual host still has no production call creating these typed buffers, while ProductionRenderer::compile_world_graph and warm_up_gameplay explicitly reject the missing world FramePasses consumer. This patch fixes a concrete descriptor bug and does not claim the GPU readback lifecycle, completion synchronization or full game execution is complete. Root owns independent review, compilation and integration.
