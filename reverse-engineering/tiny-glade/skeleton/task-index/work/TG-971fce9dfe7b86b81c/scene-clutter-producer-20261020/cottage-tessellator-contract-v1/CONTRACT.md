Setup and original order

The helper reads Roof.height before asserting rank1..3; rank factors are exact(.1,.15,.2). Let baseY=cached.translation.y, baseHeight=baseY+height_offset, topHeight=Roof.height*factor+baseHeight. Query the initial clamped Roof section at the actual cached translation (baseY), get its canonical perimeter closestU for cachedXZ, get its position atU, and lift with baseHeight. Then query/project the top section at cachedXZ/topHeight and lift with topHeight. Shape queries are actual Roof methods, not default rectangles or caller-supplied dimensions. The low32 roof identity comes from this same Roof. DistanceL of the two projected/lifted endpoints determines the row split count; no fabricated height or transformed width.

One fastrand::Rng is seeded from raw-f32 length(cached.translation*10) cast with original saturatingu64 semantics. The same stream persists through all row/column splits and every emitted record; it is never reset per row/cap. Row boundaries are utils::random_splits(max(2,saturating_usize(ceilf(L/.4))),bits3da3d70b/L,&rng). Actual import bindings for ceilf and fmodf come from the preserved B call pack/IAT evidence. Internal boundaries consume RNG before any per-row tile generation. Initial half normalized perimeter interval is (width/initialSection.perimeter())*[-.5,+.5]. Preserve division/multiplication order.

For each row boundarys, interpolate the two projected/lifted endpoint Ys as topEndpointY*s+lowerEndpointY*(1-s), then call actual inverse_lerp(baseHeight,topHeight,interpolatedY), even though algebra might simplify it. Consecutive remapped boundaries t0/t1 define rows. Iterator evaluation must not execute later row geometry/RNG after an earlier failure. No new finite/fallback predicate may drop a row silently.

Two different height pairs, not one simplified row height

Section-query/cap heights are H0=topHeight*t0+baseY*(1-t0), H1=topHeight*t1+baseY*(1-t1). Nativee2ad..e2e2 stores these inrbp+2f8/+358. Query and expand the low/high sections at cachedXZ/H0,H1. Expansion is (1-t)*expansion_margin+t*0 for each row section and returns a new section; do not mutate Roof or eliminate the zero multiplication. The two same H0/H1 references are captured by the side-cap helper atf57e/f58c.

Each expanded section gives its actual canonical closestU for cachedXZ. Row width=(expandedLower.perimeter()/initial.perimeter())*inputWidth. Column boundaries use max(2,saturating_usize(rowWidth/.3)) WITHOUT ceilf; jitter is exactbits3d75c28f/rowWidth (.06). This allocating random_splits advances the one stream before vertex-height calculation.

Only after that call, e4bd..e4f1 computes vertexY0=topHeight*t0+baseHeight*(1-t0) and vertexY1=topHeight*t1+baseHeight*(1-t1), separately from H0/H1. The first row thus queries a section/cap bottom at baseY while lifting its vertices at baseHeight. Folding these pairs together would change actual geometry/clipping when height_offset!=0.

Perimeter interval and four real corner projections

For low and high sections, take closestU plus the original initial half interval endpoints, wrap each by fmodf(value,1); add1 only when remainder<0. Negativezero/NaN policies must follow the scalar original, not rem_euclid invented behavior. Forward interpolation of a column split raises endU by1 when startU>endU, evaluates end*s+start*(1-s), explicitly rejects NaN before wrapping, then wraps via fmodf again. Keep the existing period1 curve-coordinate semantics, not angular CircularF32(TAU) storage. Do not add a second curve class.

Consecutive split outputs supply lowU0/lowU1/highU0/highU1. The original first pulls both split outputs, then guards each actual projection in order: lowU0 finite range0..1→project/liftA, lowU1→B, highU0→C, highU1→D. No projection may be performed on invalidU and no validity failure may become continue/default. Lower section projects A/B at vertexY0, upper projects C/D at vertexY1. Endpoints cached by tuple-window evaluation are reused only as pure coordinate values; shape/guard/emit side effects retain native order. Native locals are uStack220=A,uStack230=B,uStack240=C,plStack250=D (original XY pair and separate Z representation, not a new raw native Rust struct).

Each column emits the following sequence; first/last tests are independent

- If rowIndex==0, emit the extra lower lip before the ordinary body. Its width is raw-f32 distance(B-A). Take the lower section's overall original interval start/end positions and its closest center position. Lip depth=MAXSS(distance(overallSpanMid-center)+.1,.3), with original operand/NaN policy. Upper section positions at the current two columnUs are sampled to form an XZ midpoint; subtract lowerMid=(A*.5+B*.5), raw-normalize the horizontal difference and lift X0Z to Dlip. Orientation is from columns(Dlip crossY,Dlip,Y), preserving original zero products and basis-to-quaternion branch. Position=lowerMid+Dlip*(depth*.5), dimensions=(width,depth,.1). Pack quaternion and dimensions, draw one i32 seed, then emit the actual64B canonical tile. Do not consume the ordinary body's random angle first.
- Ordinary body always follows. Width=raw distance(B-A); sloped dimension=raw distance(A-C)+.1; thickness=.1. E=raw normalize(B-A), F=raw normalize((C*.5+D*.5)-(A*.5+B*.5)), N=E crossF without normalizing N. Quaternion basis columns(E,F,N). Center components retain (((A+B)+C)+D)*.25 accumulation order. Draw one rng.f32r, then angleHalf=(((r*-10)-((1-r)+(1-r)))*bits3c8efa35)*.5. Direct PE142a16d10 is -10 bitsc1200000, so this is negative2..negative10 degrees; it is not guessed symmetric jitter. Multiply qbase by exact randomX quaternion(sinf(angle),0*sinf(angle),0*sinf(angle),cosf(angle)), retaining zero products and sinf/cosf order. No extraX90 here. Pack quaternion, dimensions, then draw exactly one i32(-100..100) and emit.
- If columnIndex==0, emit the left trim after the body: direction=raw normalize(A-C), use canonical utils::rotation_from_normal then multiply the exact originalX90 quaternion(bits3f3504f3,0,0,same). Position=A*.5+C*.5, dimensions=(.15,distance(A-C)+bits3e23d70a,.2), so extension is .16, not .1. Pack then draw one i32 seed and emit. If side_cap bool is true only then call the real1362B cap with fromA,toC,side=false and H0/H1; emit its returned64B tile. The flag never disables this trim.
- Independently, if columnIndex==columnBoundaryLen-2, emit the right trim: direction=raw normalize(B-D), same canonical rotation/X90, position=B*.5+D*.5, dimensions=(.15,distance(B-D)+.16,.2), pack, one i32 seed, emit. If side_cap true, call cap with fromB,toD,side=true and emit returned tile. A single column interval therefore receives both trims/caps.

All non-cap records initialize complete canonical64B RoofTileSsbo fields: base_position from real geometry, current_height0, clipping_plane=[3c000000,7bff0000], dimensions3half and explicit zero fourth u16, quaternion4half, same Roof low32id, velocity_rotation0,animation_t1, seed, flags0/0. Cap records use their real packed plane from cced. No Vec<twohalf> or marker entry can stand in for these outputs.

The native generic emission is SparseInstanceBufferWriter<RoofTileSsbo>::push. Every caller ignores NoFreeChunks; retain every subsequent geometry/RNG evaluation even when a push cannot append. The top-level owner remains the actual AssetSsboLibrary RoofTile sparse storage plus unique full64WallId→SparseAllocation DormerTiles already integratede18/e638. Allocation/retirement/GPUflush remain those actual owners. No capacity-continue, extra BufferHost, temporary Vec-to-mock upload, second registry or fixed quads.
