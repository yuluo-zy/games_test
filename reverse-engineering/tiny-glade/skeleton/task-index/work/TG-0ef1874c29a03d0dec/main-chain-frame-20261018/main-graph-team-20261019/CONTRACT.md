## Changed executable behavior

1. Outer missing-producer guard checks only the common main prelude. The actual world-only producers are still checked by world_graph/scene consumers when selected.
2. ProductionRenderer stores the original rhapsody::Error. RenderHost::take_render_error moves that value directly to the 03 render-frame Result path; compile OOM classification uses actual ErrorKind::OutOfMemory. The application-switch anyhow chain is preserved as InvalidUsage.source, and is not part of world compile retry.
3. RenderHost::abort_frame unconditionally cancels an unfinished imported presentation/acquired lease and releases retained main CPU handles, even after the original error has been moved out. Cleanup failures are logged separately and never replace the original error. The presentation prewarm-cancel branch likewise preserves its original error.
4. Factory finish_render checks the same original failure. Frame submitted/present queued facts reset at host construction (before compile) and begin_frame. Submission is marked immediately when execute_compiled returns its real receipt, even if subsequent capture bookkeeping or export validation fails; present-queued is marked only on successful real ticket creation. Abort preserves those actual facts. Completed-frame counters must still require the whole render Result to succeed.
5. frame_observation returns None until successful main execute + export check, then records real WorldId, original App shader-library owner identity, GraphId, actual selected graph kind, session receipt.frame, fixed SyncSet, all21 draw-list lengths, final format/samplecount. Queue acceptance adds the real present point/generation. frame_present_complete checks only a matching retained real ticket, returns None when its completion cannot be observed, and never equates GPU completion/queueing with presentation completion. Primary RT denotes the original Primary RT debug algorithm, not a reduced world.
6. Existing prewarm behavior is preserved: every graph path still calls ShaderHost::prewarm and checks every retained ticket, including completed failed/cancelled tickets. The proposed pending-count optimization was withdrawn after root review because pending=0 proves neither success nor cancellation absence. No prewarm optimization or device wait_idle was added. A future optimization requires an accepted successful library generation and precise invalidation on registration/reload; this candidate does not provide that cache.
7. VermeerDebugControl receives its observed mutable changed tick before Vermeer state lookup. Events<StartupRevealFinished> is optional until the core consumer actually sends on completion; an incomplete active reveal no longer panics just because that event owner is absent. No extra default event resource is created, and event changed tick is marked only on a real send. A completed reveal with the event missing records a named host error and suppresses the completion log; EffectsHost::finish returns that error after canonical resources have been reinserted, instead of unwinding through Bevy resource_scope and losing their owners.

Vermeer evidence is a fresh bounded RNE slice @1408a82f0 /2679B, saved in evidence/vermeer-pass-rne.asm/json: debug tick @1408a8391..97, state tick @1408a8405..0b, phase gating @1408a8411, completion gates @1408a8980..89a5, Disabled write @1408a89e2, event TypeId lookup @1408a89e9..8a00, event changed tick @1408a8a54..5a. The original missing-event unwrap occurs only after phase has changed. The adapter preserves the Disabled mutation and returns a named failure at finish() without sending an event, publishing readiness, or unwinding canonical owners out of Bevy resource_scope.

## Root review correction (2026-10-19)

The earlier prewarm_pending_pipelines optimization was rejected and removed. AsyncPipelineCompiler.pending==0 includes completed failures and cancellations, so skipping all ticket waits could move a previously compile-stage failure into execution after side effects. All four original prewarm calls are restored; only the separate presentation cleanup change still logs cleanup errors without replacing the original prewarm error. Temporary pending-sync stubs are withdrawn from application under the latest instruction to skip missing files; they remain historical candidates only.

The submission fact was also corrected during root review: receipt creation sets frame_submitted immediately, before capture::submitted and export checks. FrameObservation still requires a verified actual export, so a failed frame may truthfully report frame_submitted=true while frame_observation remains None. This distinguishes work actually sent to GPU from a successfully completed application frame.
