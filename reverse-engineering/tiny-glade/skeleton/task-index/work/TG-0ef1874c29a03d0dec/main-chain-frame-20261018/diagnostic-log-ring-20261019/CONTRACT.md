# Diagnostic log-ring repair contract

This is a current hand-written rhapsody defect repair, with no claimed native task mapping or native algorithm equivalence. Root explicitly delegated this output directory; the index and other claims are untouched. Main-graph candidate remains frozen. Production/Cargo/GPU writes and test execution belong to root.

The old sequence store does not claim exclusive writer ownership. With one slot: A stores odd1, writes payloadword0, B reserves the wrapped slot, writes all B and commits even4, then A writes remaining A and commits even2. A dump can then return an unchanged even2 around mixed B/A payload. The existing stress test intermittently exposes this; a controlled after-word0 pause reproduces it deterministically.

Writer contract: preserve written() as reservation attempts, including dropped attempts (the existing fetch_add observable behavior). Each attempt uses one per-slot compare_exchange to claim a unique odd token from a strictly older even token. Odd/busy, failed-CAS, stale/equal token, and token-exhaustion attempts drop immediately. No per-slot spin, lock, wait, allocation, or retry. dropped() makes these refusals observable; its concurrent snapshot can lag written while attempts are in flight. Counters retain AtomicU64 wrapping behavior, while publication tokens are checked and never reused; a terminal exhaustion bit fails closed after the first nonrepresentable token.

Only a claimed writer writes atomic payload words. Its Release fence before relaxed payload stores and Release committed sequence remain paired with the reader's Acquire sequence load, relaxed atomic payload loads, Acquire fence and final sequence validation. Accepted per-slot committed tokens strictly increase. Readers may see old/new whole records or skip changed/in-progress slots; the whole dump is a best-effort collection, not a single atomic snapshot across all slots.

Ordering: records() sorts accepted records by reservation sequence, not by completion wall time. A delayed older reservation cannot overwrite a newer committed record. Conflict drops leave holes and do not falsely promise retention of every write call or exactly the latest capacity() attempts. At most one current committed payload is retained per slot. Every returned record is wholly from one successful writer; truncation remains55B. Existing global API and format are unchanged; dropped() only adds diagnostics.

Performance mechanism: one CAS added on successful write, one small terminal-exhaustion load, plus the existing global reservation and seven payload stores. Contention losers do not touch payload; they only count a rejection. Test scheduler callbacks are generic private methods invoked with no-op closures in production and introduce no function-pointer dispatch or allocation; release optimization can remove them. Actual M3 throughput has not been measured.

Root regression plan: run log_ring unit tests first, including deterministic overlapped writers, late reservation, reader overwritten during copy and publication-token exhaustion; then the previously failed375-test rhapsody lib suite once. Preserve the original374pass/1fail report. No broad GPU rerun is required for this CPU-only diagnostic module.
