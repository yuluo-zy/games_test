# MEI canonical library owner integration candidate

Original flush_text_render@141e9e1f0 reads actual typed TextPrimSsbo and ShapeStreamSsbo entries from the same App AssetSsboLibrary; its callback copies the actual48B primitive prefix and u32 shape words, then uploads glyphs and returns the real count. Source evidence is retained in TG-c80526daecad7e4117/meihost-20261018/{CONTRACT.md,consume.asm,upload.asm}. New UI canonical factories are delivered separately under TG-e318f677dca4437b47/render-ui-constructors-20261018. They must be integrated before this adapter.

MeiHost::from_library performs no buffer creation or fallback registration. It reads the actual canonical TypedStorageBuffers, resolves their live generation through the supplied same-App BufferHost, retains real ManagedBuffer leases and checks native device/capacity/storage+transfer-destination usage. The existing prepare→upload_batch→TextRenderer::render path uses exactly those handles; glyph atlas ownership and all rendering algorithms remain unchanged. Existing import_into_frame resolves those same buffers into the same CoreGraphFrame/session and original hashes. Current session deduplicates physical Arc identity, so canonical lazy import and MEI import cannot create a second dependency history for that resource.

The caller is required to supply the authoritative same-App library/BufferHost pair after real init_populate and before first text flush. Thin core Buffer records contain id/generation/size, not an independent host identity; do not route another App library through an arbitrary host with colliding local IDs. Existing GameLoop per-App owner selection must supply this pair. No new global handle namespace is invented here.

Library mode retains actual ManagedBuffer leases but does not call BufferHost::release on drop; that would invalidate the canonical shared slots. Existing explicitly private construction retains its old allocation/partial-failure/release behavior. If canonical producers are missing, production from_library returns the original missing-owner error; callers must not silently switch to private construction to mark full72 startup done.

The GPU fixture candidate augments the existing original_loading_gpu test, reuses all real fonts/glyph CPU producers, original Vermeer/MEI/Logo shader consumers and actual pixels/readback. Its setup registers the canonical pair through the actual same BufferHost, replaces the test-only private MEI instance, asserts both original raster hash entries resolve to the exact canonical graph resources, and after completed execution drops MEI while checking library slots stay live. This is bounded validation of canonical ownership, not real gameplay startup; no Cargo/GPU execution was run for this delivery.
