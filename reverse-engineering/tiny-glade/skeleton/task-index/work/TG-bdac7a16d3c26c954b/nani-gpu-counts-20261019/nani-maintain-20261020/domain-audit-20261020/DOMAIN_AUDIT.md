# Nani set44 domain audit — visible source, 2026-10-20

The eleven remaining rows are **eleven canonical ECS binding / producer-closure gaps**, not eleven unknown business functions. Original B registers all twenty typed ECS updates in the same backend set44 chain. Current source already contains all twenty row-view update functions and their numerical payload builders; nine have the new same-World ECS adapters. No evidence in this audit moves any of the eleven to a different original non-ECS update chain, or classifies them as unused extensions.

This is a static audit of the currently visible checkout. The whole App has not been built or run. User files including `world_frame` remain pending synchronization and may contain additional registration. “No visible caller” below does not mean the user has not implemented that caller elsewhere. No production source, frozen candidate manifest, Cargo configuration or GPU state was changed.

## The three different domains

* `GpuWorldSubsetKind` has 27 values. `NaniInstanceDesc.subset_kind` stores that enum; the descriptor is not a separate twenty-variant enum.
* The original set44 tuple contains twenty `InstanceDataMarker<T>`-filtered ECS updates. Current `instance_data::register_required_components` registers those marker **types**, and `NaniBundle<T>` inserts a marker with a descriptor. Registering a component type or an empty subset creates no entities and publishes no instance payload.
* The seven other subset values are Canopy, TreeTrunk, BackgroundTree, RoofTile, Flower, Bush and WoodenPlank. They are outside this original twenty-Query tuple. Current startup makes the forest three owned and the latter four external. This separate 27−20 distinction cannot explain away any of the eleven rows within the twenty-Query tuple. This audit does not validate those seven producers.

## Original registration is concrete

The retained full B native pack establishes this path:

* `add_backend_systems` `140942c80`: `140942e28` calls `1415f5310`; `140942e2d` writes set tag `0x2c`; `140942e58` assigns the set; `140942e9c` adds it to Update. This block has no per-kind guard or run condition. The subsequent configuration flag branch starts at `140942ea1`, after this addition.
* `1415f5310` is the complete six-member `chain_ignore_deferred` helper: build missing VAOs → rebuild VAOs → maintain → explicit ApplyDeferred → unordered twenty-update tuple → flush. `1415f5684` calls the twenty-update `into_configs` helper `14206bc10`.
* `backend44-registration-pdb.json` retains each full Query/filter/resource type; `original-set44-domain.json` copies those twenty contracts and selects the twenty named update procedures from the cached original procedure index. The exact eleven function identities, addresses and sizes are retained in `kind-domain.json`. No complete PDB rescan or re-decompilation was performed.

All native claims here are bound to B RNE `f507a6ce…` and matching PDB `2d9686b8…`; this is not a C-equivalence claim. Current row/numeric source being present is not a new claim that all its business behavior, original component schemas or runtime callers have been accepted.

## Current consumer and failure boundaries

`gameplay_startup` installs `add_mapped_nani_instance_systems` in set44. Its preflight checks only actual descriptor-bearing entities, then maintain inserts canonical keys, ApplyDeferred makes them visible, the mapped updates write real owned subsets, and the existing flush publishes dirty payloads/counts. The eleven rows have no current ECS adapters. The legacy row-view APIs being callable is not evidence that this schedule invokes them.

The separate `tg-building-runtime` descriptor/marker types and tests are different owners; they do not satisfy the actual `country_core` Query by spelling alone. Current source queries retain comments and test matches with explicit labels; those matches are not promoted to production callers.

Named atlas resolution cannot silently move one of these rows between kinds. The retained original maintain body at `14206fae5..14206fb18` compares descriptor kind to each named part, and `142070493..1420704bc` checks one-part identity/kind on change. Current create/change helpers preserve those checks. The separately investigated clutter metadata counterexamples remain real domain questions; this audit does not “fix” them by changing an original helper table or weakening atlas matching.
