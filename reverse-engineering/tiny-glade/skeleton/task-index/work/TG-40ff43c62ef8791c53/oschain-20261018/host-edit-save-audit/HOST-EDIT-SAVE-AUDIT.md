Independent current-source audit,2026-10-18. Read the current production files directly, then reused/extracted bounded original B functions; no progress/statistical report is used as proof. `audited-source-manifest.json` binds13 relevant files to their hashes. ## Reachable production path

`tiny_glade::run_game::run_game` constructs winit/Window and `run_game_thread`, then `event_loop::run_event_loop→GameLoop::new→GameLoop::run`. The explicit macOS main-thread adapter feeds actual winit keyboard/mouse/wheel events into both Bevy InputPlugin and the current numeric key/mouse resources. Cursor absolute/relative events use canonical InputCursorMoved and the real mapped CustomCursor writer. `GameLoop::frame→GameFrameDriver::frame→App::update→egui end_frame→ProductionRenderer` is a real production call path.

The async gameplay SubApp is independently updated until canonical LoadingGameComplete; only then graph warm-up and logo handoff can return it to the OS owner. Loading and gameplay have separate device-bound libraries. Loading events are not proof of edit/saving readiness.

Current gameplay Update has native numeric set3 reset_input_state, set10 mode_manager, set12 load_game, set19 wall adjustment/publication/spatial, set35 history-process/replay controls, set40 replay_wall and set41 replay bucket completion. These are actually registered in tiny-glade/src/run_game.rs. The initial OnEnter(Game) consumes NextSession and loads original TOD/weather. SessionFlow Startup enumerates saves, Update handles deletion and refresh. The real Async save thread is created by add_save_load_events_and_resources. These existing links are retained, not labelled missing.

## Confirmed production blockers

1. **OS input has no action translation consumer in this host.** run_game_thread calls register_input_events but registers only reset_input_state in3. Neither gameplay nor loading currently registers translate_input_to_cursor_moved / translate_input / calculate_input_delta / update_cursor_position or the full input helper. OS key/mouse state and queued cursor events therefore do not produce live ActionSetStates; ordinary edit, toolbar shortcuts and undo/redo cannot be driven by the OS through this source. Event registration is not an input pipeline.

2. **Ordinary editing is separate from restored replay.** install_history_and_wall_runtime registers adjustment/publication and replay, but never register_wall_drawing_resources/add_wall_drawing_cpu_systems, the canvas/hover interaction producer, history_start_recording/history_finish_recording_system, or terrain tool/CPU systems. The current ordinary wall state machine consumes UiState canvas drag and CursorTerrainRaycast; these are not supplied merely by inserting UiState::at_startup. The host has no registered normal edit/transaction lifecycle. The independently tested intro history replay→wall authority path proves that narrower direction; it does not prove mouse→new edit→recorded History.

3. **No saving system is registered in the actual host.** add_save_load_events_and_resources starts the worker, but run_game does not register save_game_system or its original43 consumer. SaveGameSyncData is initialized with sections=None; no production writer for its sections/edits appears in the workspace. Thus adding that current partial system alone still omits History/camera/TOD/chain/snapshot header assembly. The writer/codec and a live worker do not create a save capture producer.

4. **The current SaveGameCmd contract cannot carry the original event chain.** The actual type is a non-Event struct `{ data:GameSaveData }`; register_save_game_events does not register it. Current save_game_system has no EventReader<SaveGameCmd>, no ShutdownGameCmd reader and no SavingGameComplete writer. Original types/functions below explicitly have all3. Close currently inserts ShutdownGame in PostUpdate; GameLoop observes it and stops, then shuts down GPU/WSI. That shutdown path does not repair the absent43 save consumer. No source evidence supports claiming edits are safely persisted on close.

5. **Session switching is not the same as initial load.** Initial OnEnter(Game) and native loading state handling are registered, but MetaCommander::commander_update_system/configure_session_switch_systems is absent from the actual tiny host. The separate core/startup::run_game helper has it, but the actual run_game never calls that helper. Queued MetaCommand batches and menu session switches do not become a complete session-switch lifecycle merely because MetaCommander exists. The source contains explicit snapshot/post-load-domain errors, so arbitrary saved sessions remain narrower than the validated no-snapshot intro path.

6. **Do not install the entire alternative core startup helper.** core/startup/run_game.rs::register_update_systems calls input/wall/terrain/save helpers, but also mode/history systems already installed in native sets by tiny-glade. Calling it wholesale would duplicate owners/consumers and mix its named local stages with the host's45 numeric stages. Those test/local APIs are useful building blocks, not evidence the production host already invokes them.

## Minimal host patch and integration order

`candidate-live-input-subset.patch` is an unapplied current-API adapter: add the4 usable live-input consumers to stage5, keep existing set3 reset, and do not register time/mode/history again. Its explicit chain resolves the current InputCursorDelta dependency before the current translate function, then resolves actions and applies cursor motion. It repairs OS→current ActionSetStates but is deliberately a partial repair; it is not native replay/modifier support or full editing. The current host already rejects input recording options, so this patch does not promise a native recording file.

The next minimal complete integration depends on canonical core owners, not invented host resources: repair modifier/replay contracts and bind GameProfile keyboard settings; expose nonduplicating canvas/normal edit/history transaction registration with original set evidence; restore save command identity and domain capture43; then register that capture before close insertion and require actual reopen→same History/authority validation. Session commander/state handoff must be integrated with supported original outcomes and real snapshot-load handling.

Required acceptance is a real host-produced interaction, not manual history injection: OS input→action→canvas→edit authority→start/finish transaction→History; undo and redo from the same action path; explicit save plus close; disk file reread/new session→same typed History and corresponding wall/tree/terrain authority. The current narrow intro/replay/GPU tests do not substitute for that complete chain.
