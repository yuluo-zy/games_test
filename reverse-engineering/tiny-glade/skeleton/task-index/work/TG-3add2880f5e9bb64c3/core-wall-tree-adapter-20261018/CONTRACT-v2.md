# Process tree command placement adapter v2

This adds to the unchanged v1 frozen38 bundle; use candidate-v2.rs / candidate-v2.patch instead of this group's v1 candidate when integrating. Root owns TG-3add2880f5e9bb64c3. No production/Cargo compiled/edited by this worker.

Original full retained process_tree_cmds decomp and source-bound B instructions show the Move query writes position to a48B placement+0..12 and inverse_lerp reads scalar scale+12; Delete reads the same actual placement position/scale. The typed component is PrefabInstance, now the existing tuple wrapper over PlacementDataSsbo in root's companion candidate. It is not Transform, nor the unrelated88B PrefabInstanceData with threeVec/name. Candidate therefore changes only the existing query and its current Move/Delete reads/writes to PrefabInstance.0. Missing TreeStorage index remains the original warning/no operation. Once a referenced entity exists, query errors reach original unwrap_failed142268583 (Move branches1422685a4/5b1; Delete14226856f), so missingplacement is explicit expect; Delete's existing Entities.contains guard remains.

One v1 mechanical type fix is included: placement variant is i32 in TreeData/InsertTreeCmd but existing SpawnPrefabCmd.variant is u32; as u32 preserves original bits. Rotation/preplaced and all other v1 API adapters remain unchanged. Two actual ECS regressions: entity with only PrefabInstance and noTransform receives Move then Delete, with correct current position/scalar-scale audio and deletion marker; liveMove entity missingplacement preserves original failure.

Root hide/UIdelete area consumers already use actualplacement and root regression deliberately makes the old TreeStorageEntry.position cache differ. No second authoritative position/cache update is introduced. Actual Insert birth delegates SpawnPrefabCmd to the upper prefab owner; this processor does not recreate that engine or fabricate a PrefabInstance itself. The current upper prefab creation lifecycle must be connected for new trees to acquire real placement/name components.

Necessary later consumers, read-only inventory: ui_move_tree currently uses entry.position for start/offset and ignores its actual placement query; tree_move_bend uses Transform rather than original placement position and does not write the existing PlacementDataSsbo.bend_vector at+36/+40; recalc_tree_position_on_terrain_height_change mutates every Transform instead of the original PrefabInstance placement. These are not silently accepted by this v2 or converted into a whole forest rewrite. Current convert_preplaced filters/candidate-source/rock-mask dependencies remain the v1 boundary. Current process loop order Move->Delete->Insert differs from native Move->Insert->Delete (the existing original-source doc itself names the latter); this reorder is left to root decision, not hidden in this query adapter.
