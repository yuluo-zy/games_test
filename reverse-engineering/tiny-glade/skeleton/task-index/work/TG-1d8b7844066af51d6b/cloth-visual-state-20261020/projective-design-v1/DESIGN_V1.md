# xz_projective_rotation_bad shared caller adapter design

This is a bounded necessary dependency of the two owned real cottage window producers, not a new quaternion algorithm. Native B 140c911d0/513B PDB759:10116 explicitly loads x from input+0 and z from+8, ignores y, and has the same normalized128-instruction quaternion body as the already reviewed504B xz_rotation_bad, subject to input-register permutation and three dead/redefined scratch instructions detailed by the retained comparison/addendum. All four primitive bodies are complete original PE ranges, not decompiler truncations.

Proposed one canonical utils/lib.rs entry (current owner already delegated): `pub fn xz_projective_rotation_bad(direction:glam::Vec3)->glam::Quat { xz_rotation_bad(glam::Vec2::new(direction.x,direction.z)) }`. No Vec3 normalization, finite-y gate, local fallback or atan2 replacement. Existing xz_rotation_bad retains the original XZ normalization/+X invalid-length fallback/second right-axis normalization/pinned Mat3-to-Quat sign branch. Native ABI takes an out-pointer and a Vec3 pointer; this safe host by-value spelling is an engineering API, not a Rust declaration/ABI recovery claim.

If approved, append the new helper and one narrow actual-call test after the current file bytes, preserving the existing feaa source as an exact prefix and its already executed7-test math slice unchanged. The test must show y finite/NaN/infinity do not affect actual x/z results, and invalid XZ follows the same existing fallback without inventing a second algorithm. Test/root Cargo remain root-only. sampling/module list and existing helpers/tests stay byte-identical. No implementation has been written at design freeze.
