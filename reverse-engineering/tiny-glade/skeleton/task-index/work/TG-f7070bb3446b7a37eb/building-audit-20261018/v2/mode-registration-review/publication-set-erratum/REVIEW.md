The preceding frozen review's 36-edge cycle projection was insufficient to establish that Bevy could initialize the schedule. I missed Bevy0.16's independent SystemTypeSetAmbiguity rule. Its statement that after(send-function-type) can wait for both publishers is invalid: source `check_system_type_set_ambiguity` rejects any system-type set having more than one instance and any dependency/ambiguity relation. The real core_editing_schedule test found this. The old frozen report remains unchanged as an audit trail; this addendum supersedes that paragraph and the broad no-blocking conclusion until the actual graph test passes.

Reviewed root's exact four-file correction against its before snapshots. `ModeChangePublication` is a zero-state derived ordinary SystemSet. Only the late publisher installed by configure_mode_manager, and the equivalent late publisher in the separate full host, join it. The existing early Input::Control instance retains its current placement and does not join the set. The three external dependencies (terrain focus-mode, HistoryCursor, replay_mode) now target this explicit set. The existing mode->late-send .chain edge remains instance-local. Search finds no remaining before/after/ambiguous relation targeting the duplicate send function type.

This is an appropriate incremental scheduling adapter. The engine's rejected condition applies only when `set.is_system_type()`, so an ordinary derived set avoids that precise initialization failure while targeting the intended late publication. It preserves both publication algorithms, shared PreviousAppMode/event resource, input phases, actual UI projection and separate full-host installer. The full-host file changes exactly one in_set annotation. No new resource, event, parallel mode manager or original global ordering is introduced.

No additional blocking source defect found in these four current adapter changes. This reviewer did not invoke Cargo or initialize a schedule. Root must rerun the actual joined-graph test; a reduced static DAG alone does not validate Bevy hierarchy, ambiguity or parameter-access constraints. Exact current/before source hashes, adapter diff and the pinned engine check are retained. History lifecycle review is separate and pending its final frozen candidate at this addendum's creation.
