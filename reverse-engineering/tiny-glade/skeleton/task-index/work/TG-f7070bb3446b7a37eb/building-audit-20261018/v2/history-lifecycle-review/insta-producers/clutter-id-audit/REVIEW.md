# AutoClutter generated ID is not UI Entity bits

Original ui_convert resolves the clicked Entity before calling handle_rmb_autoclutter. The real query is `(Entity,&AutoClutter,&AutoClutterConvertableToDecoClutter,&Transform)`. Its call at0x14099d8c0 supplies param5 DeletedAutoClutter map from rbp+88, param6 &AutoClutter from R11, param7 InstaCreateDeco writer from rbp+10, param8 History from rbp+c8, param9 AppMode from rbp+288. Native helper body saves these params at newSP+f0/f8/100/108/110. It never receives the UI Entity as a history deletion ID.

At0x140977063 it reads param6's first qword (generated AutoClutter ID). At7066..706c it calls HashSet insert with param5 map and this generated ID. Later7120..7126 starts History recording,7132..7155 allocates Arc `{strong1,weak1,generated_id}`,715e writes EditType tag13 and7176 calls actual History::add. The same generated ID thus controls both current deletion authority and undo/redo payload. Current recovered helper previously omitted the set insertion and used RmbAutoClutterHit.0 (clicked Entity) in its history edit. Conversion could leave old clutter visible and record the wrong deletion ID.

The minimal current-design correction adds an explicit generated clutter_id field to existing AutoClutterRecord, uses complete Entity bits only to resolve the record, inserts record.clutter_id into existing DeletedAutoClutter and writes that same ID to history. Fixture Entity42/clutter73 should demonstrate identity separation. No production defaults should fabricate a generated ID from an Entity.

`native_clutter_id_probe.py` executes original7060..7071 and7120..717b for four generated IDs, including73 and full64-bit values. Std HashSet insertion is observed/bridged as a dependency (not a recovered set implementation). Actual History::start_input_recording, Arc allocation and History::add execute; no game History leaf is bridged. All four native pending edits have tag13 and Arc payload equal to the inserted generated ID. Rotation/mesh conversion/creation writer are not executed here and have separate evidence. Original caller/helper asm and bound interfaces remain in the parent23-file pack. A local pinned copy of the already audited history native-harness prefix keeps reruns independent of the lifecycle author's changing candidate files.
