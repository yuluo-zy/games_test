## Confirmed finding

**Stationary point weighting uses roundf, not ceil.** Candidate draw_wall.rs `stationary_point_weight` applies ceil twice. The original code at `140a7d590` and `140a7d5a4` calls the same thunk `142923fa0`. The exact original thunk bytes are `ff25f2f18600`, which resolve to IAT `143193198`. Independently parsing the original PE's import table identifies `api-ms-win-crt-math-l1-1-0.dll!roundf`; LLVM symbolization separately agrees. This is direct callee identity, not an inference from a decompiler's unnamed math calls.

The original formula is `max(roundf(60 / roundf(1 / maxss(delta, 1e-5))), 1)` followed by saturating float-to-u64, wrapping addition into the old point weight and inclusive integer clamp1..50. Native constants at `1429d18cc` and `142950d70` are bits42700000 (60) and3727c5ac (1e-5). The existing curve resource already owns the final wrapping addition/clamp. A frame delta0.04 produces increment2 in the original, whereas v1 produces3; this changes subsequent weighted smoothing. Replace both ceil calls with round and add non-integral-ratio cases, retaining v1 frozen inputs. Author and root were notified; author accepted the finding and is preparing additive v2.
