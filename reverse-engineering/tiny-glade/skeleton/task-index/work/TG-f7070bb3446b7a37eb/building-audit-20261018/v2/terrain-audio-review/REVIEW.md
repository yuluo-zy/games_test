# Independent B terrain audio batch6a review

Reviewer: building-audit-20261018. Reviewed author frozen-inputs.json (19 entries) plus the current root integration of terrain audio initialization/order. No production source or Cargo commands were run by this reviewer.

## Findings

1. **P2, native numerical boundary mismatch, candidate supplied.** `terrain_audio.rs::clamp01` used `value.max(0.0).min(1.0)`. Original `0x141461fb5..0x141461fc0` executes MAXSS with the computed value as its source, then MINSS with that result as its source. The original thus preserves a computed NaN and negative zero. The reviewed helper returns zero for NaN and positive zero for negative zero. The added original branch replay (`one-shot-boundaries.json`) observes tag4 zero/zero -> `0xffc00000`, NaN magnitude -> NaN, negative zero magnitude -> `0x80000000`; positive/negative infinity clamp to 1/0. `clamp-native-boundaries.patch` changes the existing helper to `value.clamp(0.0,1.0)` and adds one actual consumer regression covering these five inputs. Tests compare NaN semantically, other results strictly by bits: x86 arithmetic NaN sign/payload is not a portable Rust/ARM promise. This fixes the shared helper used by tags1/2/3/4 without a parallel algorithm. `clamp-manifest.json` binds the exact current root base and candidate; apply the patch hunks, do not replace the full candidate over later root edits.

2. **P1, existing loop clock consumer remains incompatible with the current hand-refactored helper.** The frame-end terrain consumer calls `AudioLoop::stop(Duration::ZERO)` every silent frame. Current `utils::audio_utils::AudioLoop::stop(now)` initializes `start=Some(now)` and returns while `now-start <= threshold_ms`; repeated zero never exceeds any threshold. A loop started by a prior edit can therefore remain started indefinitely. Current init-once repair removes the accidental per-frame reset which masked this behavior. Independently extracted original `0x140a59430`: first stop calls the monotonic clock helper `0x140d635e0`, subsequent stops call elapsed `0x140d63910`, then compare elapsed milliseconds against +0x30. The original does not receive game clock/replay delta from terrain. The needed incremental adapter must supply advancing monotonic time to the current helper and retain deterministic control for tests; using paused GameTime would change original behavior. This finding is outside the frozen batch6a patch. Reported to root for coordinated ownership; do not mark full loop lifetime complete yet.

3. **Root-added lifecycle test assertion, not production failure.** `registered_audio_keeps_its_loop_owner_and_consumes_this_frame_producers` asserted one Create per name. Current `AudioLoopDesc::new(name).count == 3` and `AudioCore::instantiate_loop` creates that many instances. Two schedule runs should still produce three per loop name, rather than six. Root was notified to fix that expectation. The one-shot recorder observes exactly the existing Studio/EventInstance traits and supplies no replacement audio engine.
