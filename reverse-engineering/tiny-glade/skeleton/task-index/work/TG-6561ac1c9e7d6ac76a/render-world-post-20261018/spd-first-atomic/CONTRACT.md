# Original SPD temporal atomic producer and view consumer

Scope: B only, native source semantics integrated into the current user-refactored Rhapsody architecture. No production edit or Cargo/GPU run by this worker.

Native get_or_create_temporal<Buffer> 0x1404f62d0 creates a CPU zero vector of the complete requested size using __rdl_alloc_zeroed, passes its nonnull pointer and length to GraphicsDevice::create_buffer<Option<&[u8]>> 0x1405b93b0, then frees the CPU vector. The exact allocator trampoline, PDB allocator identity, PE GetProcessHeap/HeapAlloc imports, Option byte_count/copy_to_slice and staging setup ranges are included in zero-upload-proof.json and native manifests. It still imports initial access0 and explicitly returns history flag0. Thus allocation contents and confirmed frame history are separate facts.

The producer candidate only changes actual named temporal buffers. It uses existing Device::create_buffer(Some(bytes)); concurrent resources preserve existing sharing and managed upload. Plain raw buffer None and all named textures retain their present behavior. The new private owner initialization fact has default false; only the successfully uploaded actual buffer owner supplies true. Cancelled unsubmitted frames retain those bytes. Reset and partial submission revoke the fact; successful graph export publishes history separately. Existing strict uninitialized-read checks remain.

Native rg_binding_to_descriptor_binding 0x14205eff0 and its custom closure inside fold 0x1418b46d0 prove individual-mip descriptors: remaining=mips-base, iterate base..end, one level per view. The host previously used full_count plus nonzero base, then bound only a single descriptor. Candidate04 fixes both declaration/record projections and binds each original view through the existing parameter heap. The current fully-bound ABI additionally aliases unused tail entries to the last real view/lease within the already declared range. This is an explicit host adaptation; it does not claim original tail initialization. Packaged SPD gates every tail store by mips>element, and for this 9-level fixture push mips8 prevents access8..11. Guard and ordinary scalar bindings are unchanged.

CPU candidate exercises uploaded initialization independent of history, cancellation, confirmation, partial submission/reset, exact mip/layer projection, per-mip views and ABI capacity errors. Strict GPU fixture uses a fresh 256x256 9-level image each of two frames and initializes mip0 only, changes red to green, reads all five packed pixels of mip7/8, checks original Generate mips remains live, checks the real SPD atomic owner is reused with history false then true, and copies a separate actual 24-byte named zero-upload probe to host memory. The actual SPD atomic usage stays native0x20 (+real transfer-dst upload), without adding transfer-src to inspect it. Last-mip generation indirectly exercises original cross-workgroup atomicAdd/reset; the six actual SPD counter words are not directly read back.
