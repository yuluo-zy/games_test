# Current freehand curve and terrain readback boundaries

This is a current-source consumer audit, not a claim that either complete chain is restored. Twelve inspected source hashes and four missing-source checks are retained in current-consumer-fingerprints.json. TG-772e8f649ffb32fc5a was legally unclaimed before this worker claimed it; only this work directory was written. No shared registration, production source or Cargo state was changed.

The actual tiny-glade/src/run_game.rs has advanced: it now installs the existing History/ReplayBuffer, actual CPU terrain height owners, shared Path publishers, real wall publication and original numeric history sets35/40/41. Earlier descriptions that all host history/wall startup was absent are therefore stale. Those additions do not include the freehand input producer or a terrain world graph.

Current country-core has no systems/wall/draw_wall.rs or ui_draw_wall.rs, no resources/drawing_input_smoother.rs and no resources/walls/in_progress_wall.rs. Workspace references to the restored InProgressCurve resource are initialization, its own regressions and read-only snapping consumers. There is no production raw-point append/finalization caller. The resource's instruction-backed algorithm acceptance remains valid, but it is not an accepted live drawing chain.

The original B draw_wall is a13557-byte function at0x140a7cba0. Its original byte/source pack and exact matching-PDB FunctionSystem spelling are retained. The actual reader is RecordMouseInputIntoWall. Other parameters include current InnerWalls plus original InProgressWallResource, CurveNursery, a tuple of SnappingMode/CursorTerrainRaycast/ContinueWallOriginalState/GameTime/MainCamera/WindowSize, material audio and height commands, color-id owners and pinned-clutter notifications. The original body calls DrawingInputSmoother::process, InProgressCurve::new, three raw append paths and two final-curve paths. It is not a single new call from existing snapping. Several producer/state owners are missing; adding an isolated new helper or a fabricated event would not close that chain. Current InnerWalls already has creation/curve-update APIs and must be reused when this actual endpoint is recovered. No legacy wall engine should replace it.

The typed MouseTerrainRaycastSsbo constructor/pass declaration/read provider and TerrainRockMaskSsbo constructor/sampler exist. Current render_bridge::install_asset_libraries preserves and initializes the real typed SSBO table, but no inspected production path creates the mouse/rock entries. Actual ProductionRenderer::warm_up_gameplay and compile_world_graph explicitly return the missing world FramePasses consumer error. The country-core render_world interface lists the mouse pass, and read_terrain_data declares the height/mask passes, but the actual host does not call them through that absent world consumer. Thus real GPU construction/submission/completion-to-CPU-read acceptance remains open. Current graphics/asset ownership improvements remain usable and should not be replaced with a new runtime graph.

The constructor audit did identify a bounded actual bug and produced a separate minimal candidate under TG-cc0ba74837cd6c20eb: TerrainRockMaskSsbo used0x8000 u32 elements and the wrong short name, while the original constructor requires0x8000 bytes/0x2000 words and TerrainRockMask.
