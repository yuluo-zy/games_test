# Minimal live sheep save adaptation

Current save_game_system and sheep_save_section_system both read debug SheepControl.snapshot. That is a freeze snapshot, not the live query capture that original save_game performs. Correcting freeze lifecycle would expose this existing separation bug: default None is serialized null despite live sheep.

live-sheep-save-only.patch replaces only the two system parameters and their capture calls, reusing the current pure capture_sheep_snapshot on Query<(&Transform,&core Sheep,&CritterGoal)>. Both writes serialize Some(&snapshot) even when the query is empty. No duplicated serializer or sheep algorithm is introduced. Debug and save can now preserve separate lifetimes using current architecture. The producer must run before assembly; SheepSaveSectionValue initial None is an unproduced state, not a rule for a zero-row world. Root owns shared registration and current save file changes.

Some-empty is not guessed: fresh native0x140a51d40 is the original to_json_string<Option<SheepControlSnapshot>>, branching only on first-qword i64::MIN niche. Host original execution (sheep_option_native.py) confirms None→null; ordinary zero-capacity Vec with zero rows→{"sheep":[]}; nonzero-capacity/zero-row Vec gives the same object. Original save_game0x140a3f470 unconditionally calls FromIter<SheepSnapshot,Map<QueryIter...>>0x141304bd0 and carries its ordinary Vec result as the Option storage; the retained save decomp has no empty-length-to-None filter at capture. Existing X4/query and fields are already supported by root's capture/apply native pack and are not re-mined here.

Verification limits: three original Option serializer cases; no full original save process/ECS/file roundtrip. Root will compile the proposed current Rust query signatures and validate live default/unfrozen saving. The distinct system-critters Sheep component is not silently treated as core Sheep; any cross-crate identity reconciliation remains a separately required integration task.
