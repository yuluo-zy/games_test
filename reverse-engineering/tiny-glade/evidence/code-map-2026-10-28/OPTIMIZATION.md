# Tiny Glade 查询优化实测，2026-10-29

**优化已实现，返回内容与原实现完全一致。** 本轮针对本地读取接口和符号搜索，没有重建或迁移原图，也没有改生产 Rust。

同一快照 `053060f0c5d388b353567d8b`，相同 12 项任务，每项 30 次。分段计时中的任务中位耗时从 15.33 ms 降到 1.00 ms，降低约 93.5%。独立正式基准中图查询为 1.93 ms、rg 对照为 3.62 ms，这组热定位任务的图查询快约 46.7%。

## 根因与修改

1. **客户端初始化是普通查询的主要固定成本。** 复测旧 `load + build_opener` 表达式，中位耗时 5.46 ms；旧流程通常每个请求建两次客户端。现在配置按文件身份缓存、HTTP 连接按线程复用，客户端构造约 0.037 ms。认证仍启用，异常事务不自动重放。
2. **符号子串搜索走了昂贵的全文通配符路径。** 改用 Neo4j TEXT 索引支持的 `CONTAINS` 查询，[官方索引说明](https://neo4j.com/docs/cypher-manual/current/indexes/performance-indexes/create-indexes/)。实际 PROFILE 包含 `NodeIndexContainsScan`；查询本身无数据更新。
3. **长 Rust 泛型需要单独处理。** 直接给所有名称建 TEXT 索引真实失败：有 34,767 字节名称超过单值限制。最终短名直接索引，307 个长名使用 733 个重叠分片；完整原符号保持不变。相邻 8,000 字符分片重叠 511 字符，覆盖接口允许的全部 ≤512 字符搜索。
4. **将快照检查与实际读取放在一次 HTTP 事务里。** 每次仍重新读取完成状态；实际查询也带 `complete:true` 保护，不缓存完成状态。普通固定快照查询由两次 HTTP 往返降为一次。
5. **证据校验未降级。** 原先实测哈希约 0.5 ms，继续逐次重算；没有为了微小收益改成跳过校验。

派生索引只针对已发布快照构建，构建完成前不启用；旧快照或缺少投影时保留原搜索路径。CLI 新增 `optimize-search`，新快照发布后可重复运行。没有删除历史快照或清理原证据。

## 结论边界

这次证明的是**相同结果的查询接口显著加速**。输出字节未减少，仍为正式基准记录的 25,195 字节，对照锚点输出 6,096 字节；没有宣称上下文减少 50%。

完整逆向任务的模型时间、人工步骤、真实工具往返、原程序业务差分，以及全软件语义拆分，仍没有由这些毫秒级热查询结果自动得到验证。初版的“图查询比 rg 慢约 78%”已被本轮热定位复测更新；整体工程验收条件仍需独立评估。
