## 真实链与可靠性

验证链为：屋顶触发网格 → 更新碰撞 World/receipt → 全局 raycast → 最终 winner 的 UV/法线转换 → terrain 合并 → Raycasting 消费者。

- [全量检查](verification-full.json)：233,677 个 B 范围重新核对原字节，602,041 条直接 CALL 记录与 rel32 原编码一致。
- 六个冻结入口范围用独立 `llvm-objdump` 交叉检查全部通过，包括原 31,293B 更新系统和 14,692B 屋顶入口。
- [业务图查询校验](verification-chain.json)：冻结的人工合同关系无遗漏、无额外错误确认边。此项证明已审查注释的保存和查询正确，**不证明图自动发现了这些业务语义**。
- [真实 MCP 验证](mcp-smoke.json)：搜索、状态使用者、去重汇编、dispatch 补证和未绑定原文读取成功；写工具和未发布快照被拒绝。
- 12 项故障/边界测试通过。错误 SHA 的真实 collector 请求退出 2；损坏 blob、错误版本、越界深度、截断、缺少独立范围均不能被当成成功。
- [持久性](persistence-final-result.json)：正常停止并重开同一数据库，实体数、关系数和链路签名一致。重启后首个函数查询为 0.890s；未清操作系统缓存。

两条历史游戏验证收据分别有 25/26、36/37 个文件指纹仍匹配，均有一项当前 `world.rs` 指纹变化，见[收据审计](receipt-audit.json)。因此本次没有把历史 native/Rust 测试通过升级为当前生产实现通过，也没有重新运行整游戏、OS 或 GPU 验收。

## 实测性能与便利性

主批汇编提取约 118s；最终图导入 274.16s，无变化导入约 10.27s。导入进程最大 RSS 为 135,888,896 字节，另有独立 JVM；这不是整个系统的峰值内存。最终全量字节复核 25.36s。

分层汇编约 381 MiB；运行时合计约 18 GiB，其中 Neo4j data 约 16 GiB，包含旧快照和中断快照。数字为现场 `du` 观测，不是单个活跃快照的独占大小。没有清理原证据以获得这些结果。

## 保留的失败与修正

1. 首轮并行写清单发生 SQLite 锁冲突：保留日志，顺序续跑，并给 CLI 写阶段增加互斥锁。
2. 范围 owner 查询缺少索引导致导入停滞：仅中断本任务进程，补索引后幂等续跑，未完成快照不发布。
3. 旧屋顶报告写 12,048B，实际 B PDB 范围 14,692B：记录分歧、修正独立基准，并补“缺范围不能汇总为通过”的回归。
4. 两个 dispatch stub 的 Ghidra body 仅 1B：保留原范围，另保存独立 LLVM 核准的 2B/6B 首个无条件间接转移。运行时目标仍未知。
5. 直接在图中对符号别名做模块聚合出现笛卡尔展开和事务超时：改为对绑定同一发布快照的规范化清单去重投影。
6. 消费者证据包最初被大量传入路径挤满：改为默认追踪向外依赖，12 项导航复测全部正确。

首轮失败、修复前基准及原 collector 冷/暖缓存记录保留在本机运行目录；最终通过项只引用上面的最终结果。
