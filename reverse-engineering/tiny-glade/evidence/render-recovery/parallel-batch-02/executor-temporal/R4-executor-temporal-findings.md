
Observed chain: `GraphExecutionRecorder::execute` (`0x1400fb5b0`) calls `execute_compiled` (`0x1400fa190`). The latter constructs `BatchCompiler`, flushes each graph batch (all passes when the executor flag is clear; per-pass boundaries when it is set), calls `CompiledRenderGraph::record_batch` (`0x1402c1d40`), then `ResourceRegistry::into_exports` (`0x140be9040`) and `ExecutedRenderGraph::new` (`0x140bea180`). `record_batch` records command buffers and ends all but the final buffer for export barriers; it does not submit a queue.

`submit_pending_cbs` (`0x140bebdf0`) is the submit boundary. It moves pending command-buffer records out of the recorder, builds submit data, calls public `GraphicsDevice::queue_submit` (`0x140c04e20`), and stores the returned 16-byte completion token at recorder offset `0x108`. `ensure_active_cb` (`0x140bebc90`) lazily allocates the active command buffer and seeds the per-frame command-buffer state. `end_frame` (`0x140bec400`) closes/disposes active state, invokes `submit_pending_cbs`, updates frame sequence data, and places the submission record into the executor frame queue.

The lifecycle is deliberately split. `execute_compiled -> ExecutedRenderGraph::retire` performs immediate CPU graph cleanup and moves remaining resources/exports; `retire` (`0x140be9d00`) contains no wait or completion-token test. GPU destruction is deferred by R3 managed-handle tracking and queue completion (`wait_submit_done`/disposal buckets). Do not require retire to wait for the GPU.

`ExportedRenderGraphResources::take_resource` (`0x140be9c80`) hashes a logical key, extracts the corresponding exported resource payload, and panics on the empty/missing variant. `ExecutedRenderGraph::new` copies the graph/resource-export aggregate into the executed wrapper. `GraphExecutor::new` initializes a 0x1b8-ish executor state including frame queue and queue/device handles. `begin_frame` (`0x140beabd0`) rotates old frame records and calls `GraphicsDevice::wait_submit_done` as needed. `wait_gpu_queue_trim` (`0x140bea680`) optionally waits on the oldest submit and uses R3's wait-duration primitive. `last_known_frame_duration_ns` (`0x140beaae0`) returns a bounded duration estimate from timestamp history and device calibration.

`TemporalRenderGraphState::get_and_flip_parity` (`0x140beced0`) is a hash-map operation at state offsets `+0x30/+0x38/+0x48/+0x50`: a hit returns the old `u32` parity and writes `1-old`; a missing key inserts zero and returns zero. `TemporalRenderGraphRecorder::export_temporal` (`0x1404f7ca0`) iterates temporal resource slots, updates temporal payload records, and copies the resulting map/resource aggregate into the graph recorder. Exact user-data/resource payload types remain unresolved.

R2 supplies compiled batches, access/barrier plans, and `into_exports`; R3 supplies command-buffer tracking, submit sequence, completion, and reclaim. R4 returns immediate exports/remaining resources and temporal parity state to R2 while R3 independently controls GPU-safe destruction.
