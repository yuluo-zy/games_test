# Rhapsody parallel recovery batch 02

Batch 02 advances three connected recovery units in parallel:

- R2 graph compiler integration: declarations to a deterministic compiled snapshot.
- R3 GPU lifecycle: managed handle use through submit completion and reclamation.
- R4 executor and temporal state: compiled batches through submission, retirement, exports and next-frame history.

`contract.json` is generated by `scripts/render-recovery/build_second_batch_contract.py`. It fixes the selected entry points, cross-package interfaces and acceptance gates before manual semantic recovery begins.

The batch does not claim full Vulkan execution or original Rust ABI. Public library behavior remains an external dependency boundary, and country-core closure bodies remain outside generic rhapsody recovery.

## Result

The three work packages are now delivered:

- R2 produces a deterministic CPU compiled-graph snapshot from the graph DSL. Seventeen projection tests and four snapshot fixtures pass.
- R3 closes the tracked lifetime event model from use and last CPU drop through command completion and disposal. The native leaf oracle passes 29,692 original-instruction cases.
- R4 recovers the executor/temporal timeline as backend events. Four candidate tests pass; CPU retire is immediate and GPU disposal remains deferred through R3 tracking.

Run `python scripts/render-recovery/validate_second_batch_contract.py` to regenerate `integration.json`. The gate checks the corrected reused-resource barrier split, separate command/timeline domains, immediate CPU retirement, deferred GPU disposal and per-key temporal parity.
