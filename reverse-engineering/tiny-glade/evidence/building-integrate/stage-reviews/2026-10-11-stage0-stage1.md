### 独立执行和代码核查

审查者没有运行会写报告的正式 verifier。只读加载报告 `input_cases`，使用其 `make_line` 编码送入冻结 release probe，同时重新执行 `native_production.produce(**case)`，比较完整有序 bytes 数组。

另从正式案例索引 `[0,1,12,28,72]` 深拷贝 5 例，每例设置 `holes_length = length * .75`，holes 为：

```python
[
    ([-.1, .1, .7, .6], 2, 1),
    ([length - .1, .4, length + .3, 1.1], 1, 2),
]
```

这些案例补查非零 origin、不同 finalized-hole length 及 open/closed 组合；仍只是明确源输入域差分，不证明其全部组合出自当前 World。

每次原码执行后另外断言 `cpu.reg_read(UC_X86_REG_RIP) == stop`，排除 emulator 的 10M instruction count 上限静默截断。结果：**90 cases / 7075 records，全部完整有序 96B 数组 byte-exact，nonreturn_cases=[]**。这 90 例是独立审查补充，不改正式报告的 85/6476 计数。

核对项：row/boundary seed 混合与 wrapping、逐 row 和逐 column RNG 消费位置；先消费 split/depth draws 再执行 skip；原 row upper × max-height authority 筛除；顺序 coordinate walker 的 start/mid/end 三数组采样；被跳过列后的噪声缓存策略；原 `[-100;3]` sentinel；width padding / thickness Option 的原分支默认值；原 curve point/U/length 复用与输出顺序。未发现实质缺陷。

oracle hooks 限定通用 allocation/free/reallocation/memory、IAT 识别的 CRT 数值调用及禁用 profiler；private row、RNG、Curve、hole、proposal 和 instance 指令真实执行。candidate 接收一次真实类型的源数组/scalar/options，不注入捕获 proposal/context、per-proposal RNG draws 或期望记录。原 caller 允许条件与 typed Curve2/source-owner 数据域是前提，不扩大为任意损坏 ABI 的行为证明。
