# Startup tree chain acceptance handoff

The original shipped `assets/starting-builds/{full,demo}/intro/history.json` files are both version16. All remaining shipped starting histories are version17/18. Every new-session starting build therefore requests the <19 preplaced-tree path, not only user old saves. `shipped-assets-inventory.json` binds original assets by SHA256 and applies f32 strict position filtering: summer270, olden198, flowery159, autumn281, winter160 accepted before terrain/wall filtering.

`startup-chain-acceptance.patch` adds a test submodule to the real system-tree converter. The two regular tests exercise real prefab runtime and actual full typed mapped mask (0x2000 words, including a nonzero sampled bit), actual four path/water/garden rasters, actual occupied wall cell and nonempty History. They require one accepted Place, five distinct rejected trees, skipped dead/missing query entries, exact third-update timing, event-batch coalescing, and no spontaneous edit without a legacy event. Prefab runtime must insert the canonical placement component first and create six actual Nani instances. No placement component is directly synthesized by the test.

The asset-dependent ignored test runs the actual asset producer, actual prefab runtime and actual delayed converter for every shipped theme and checks all48 placement bytes, tree indices and attached audio/component owners against the real files. It requires the test process working directory to be the original distribution directory; it never changes global cwd and never writes original assets. Per-name one-part prefabs are bounded test fixtures, not a claim that full asset-prefab loading or physical GPU readback was validated. CPU-device boundaries retain full mapped storage. Root should run the two regular cases during its normal build checkpoint; run the ignored single case with the original distribution as cwd and an absolute workspace manifest/target path.

All three tests currently have only rustfmt parsing validation. No Cargo command or test execution was performed by this owner. The patch has exact raw base/proposed SHA256 manifest; root owns application and execution.

## Completion and schedule contract

Actual load_game Update state0 writes SpawnPreplacedTrees after installing History; state1 publishes signed history commands and sets state2; state2 sends LoadingGameComplete. Original converter consumes the request, stores count1, returns; the next call reaches2 and returns; the third reaches3 and performs conversion. No original ready gate waits for a converter flag, GPU readback, replay buffer or StartupReveal. Independent flow owner confirmed the original load writer tuple has no StartupReveal writer. The unused request_reveal host field must not become an invented wait. Keep remaining reveal/audio ownership explicitly unknown until original producer is located.

The current shared host must register spawn_preplaced_trees on Update/in_state(Game), never OnEnter, because its request is written later in load_game Update. It must register the converter against the same event and allow the actual prefab runtime and its deferred commands to run before the delayed query. Existing prefab runtime consumes events after stage40/before41, guarded by the real canonical startup owners. Missing owners currently skip that lifecycle; they cannot be replaced by an empty-mask/empty-prefab proxy or interpreted as a successful complete startup.

The original loader completion and converter remain parallel consumers; adding a new loader blocking condition would change game behavior. check_load_completion sticky marker/unlink is independently owned by independent_flow_wiring. Root owns the actual production App registration and schedule acceptance.


## Preferred integration target

Root requested a separate integration test to reuse already compiled production libraries and avoid system-tree libtest codegen. Use `startup-chain-integration.patch` and its manifest instead of the earlier converter submodule patch. The new file is `tiny-glade/crates/tiny-glade/tests/original_preplaced_startup.rs`; all three acceptance bodies are retained and the actual owned Nani subset instance count is also asserted, not only the requested-count accumulator. It imports real public system_tree/core entry points; no source/Cargo file is modified. For the ignored asset test, execute the compiled test binary directly with the distribution directory as its process cwd. Invoking Cargo from that directory is insufficient because Cargo sets a test target cwd to its package root.
