## Implemented path

The session-owner review hunks for `load_game.rs`, save tests and startup test calls were integrated; root integrates the actual session/startup owning request files. `parse_saved_game_data(path, &GladeSettings)` now produces all four metadata bits for every accepted version. It no longer rejects an already parsed old save merely because migration metadata is absent. Missing/invalid Colors use the original settings-aware defaults. UI-owned `Box<ParsedGameData>` moves through the load source without cloning or reopening history.json.

New `country-core/src/systems/save/load_game_migration.rs` restores the original non27 compatibility policy using canonical typed history owners. The raw JSON prepass handles only removed `MarkEnclosure`, validates its required typed fields, and then feeds the ordinary history decoder. It preserves `wall_index`, complete ShapeParameters and both directions: `is_valid=true` is No→PremadeShape, false is PremadeShape→No. Other malformed payloads still fail typed decoding; there is no empty edit substitution.

The migration covers WallChanged equal-coordinate operation repair (only operation tags0/1), Terrain's exact two-point zero-distance correction, pre20 Gate/Decorator ColorEdit's independent from/to map, pre16 decorator auxiliary-map clearing, and original retain behavior. Retain always removes EditType::Decorator(tag11); only pre16 additionally removes DecoratorV5(tag10) and Color::Decorator(target7). Before/after auxiliary states both receive pre20 window mapping and pre21 ArrowSlit999. A matching record sets the corresponding metadata flag even if its numeric value already maps to itself. The native potential-mutation boolean stays independent from those two flags.

Pre17 terrain migration writes **height**, not falloff: NewTerrainStroke.height_ws = clamp(sqrt(height)*10,0,20), and the same transformation independently applies to EditTerrainStroke.prev_height_ws/new_height_ws. Falloff fields remain intact. The SSE unordered/signed-zero behavior is preserved explicitly instead of using Rust f32::max/min NaN selection. A native migration mutation clears parser history snapshot references and replaces the same parsed History identity using the original fastrand dependency; no clock-based counter or extra Identity resource is added.

Window bit40 and ArrowSlit bit48 helper names/semantics are now consistent throughout `resources/save_file.rs` and `load_game.rs`. The old names had described the opposite algorithms, so merely swapping flag accessors would have preserved a bug. Bit40 maps GateColors and all three window Decorator types. Bit48 sets only ArrowSlit to999. The canonical state color field is the low32 bits of `DecoratorHistoryState.u28`; its upper32 seed and u34 window-light color are preserved.

The World load path applies snapshot compatibility before domain writes. After successful snapshot application it writes the selected snapshot's actual chain index into canonical History.cursor and sets replay delta to target−selected, preserving negative deltas. Previously it retained cursor−1 and replayed the whole saved chain over an already applied snapshot. Only bit40 invalidates the History snapshot-reference list after application. The async OpenFile command now remains local until snapshot application succeeds, so a snapshot failure cannot start rewriting the save first; bit40 invalidation also reaches the initial saved Snapshots section. Saved history_start−1 is retained verbatim, rather than clamped to0.

Wrapper+c gates the Path-source upgrade backup together with `!new_session`; backup failures propagate through the existing failed-load route. Parsed UI/backup requests do not reopen a disk path. Wrapper+f (`version<19`, historical field name `legacy_version_notice`) writes the canonical **SpawnPreplacedTrees** unit event after canonical History publication and before selecting/applying the snapshot. It is neither a settings-save event nor DisplayCorruptedSaveFileWarning. `SpawnPreplacedTrees`'s old `_gap:u64` was removed because the native EventInstance contains only its8B EventId. Root must include the same event in its canonical assembly; tree-tool already registers it.

## Identity

`save_file_identity.rs` now follows the original leaf exactly: hash `path.file_name()` (the Option itself), hash the tuple `(previous_hash, &metadata.len())` on metadata success, then `(previous_hash, &metadata.modified())` on modified success. A failure returns the hash prefix reached so far. This fallback never reparses Identity and never queries the current clock. It reuses existing `utils::calculate_hash` and std metadata APIs; std was not reimplemented.

`HistoryTransactions::identity/set_identity` project the existing ledger.mutation_nonce, the same native History+60 owner. Active loading now preserves parsed.identity into that owner rather than writing0 after serde. Existing recording/branch/potential-mutation functions replace this same field; existing save publication reads it. The idle startup `History::empty_glade()` still sets0 and its original inlined constructor has not been independently established here; do not classify that constructor as recovered based on this active-load fix.
