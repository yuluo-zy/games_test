## Shared type closure and API

Existing draw callbacks used three isolated *View component types, while no actual AlbedoMap/AlphaMap/NormalMap producers existed. Candidate canonical eight-byte components are added to components::drawable and components::NormalMap; old callback imports become re-exports of those exact types. Startup producer and texture consumer therefore use one ECS TypeId, without a mirror view resource. This is a narrow type-owner correction, not a render algorithm replacement.

`startup::glade_themes::{startup_olden,startup_flowery}` take root, mutable placements, graphics device, active session, mutable Commands, MeshWatch, MeshLibrary and ShaderLibrary, in that order. Olden returns Result<PreplacedAutoClutter>, Flowery Result<()>. Main clearing owner color_menu_full agreed this contract. It owns branching and register/remove lifecycle; root owns OnEnter registration/build.

The helper includes six exact original rectangle bit-goldens and canonical/view TypeId assertions. These Rust tests have not been compiled or run. Original fixture execution alone must not be relabeled Rust acceptance. Remaining App validation must use actual clearing startup/shaders, actual instance maintenance and material texture lookup. Main clearing, ForestTree ownership and loading/GPU completion are separately coordinated.

The exact original Flowery quaternion payload also proves signed-zero X/Z channels for negative sin(half-angle). Candidate uses the existing glam axis-angle constructor, not its specialized Y constructor, and adds six native quaternion bit-goldens. This keeps the original zero multiplications rather than discarding their observable signs.
