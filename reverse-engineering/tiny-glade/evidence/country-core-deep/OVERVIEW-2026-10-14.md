## 1. 工作背景与方法

对 Tiny Glade 原作（B 版，`tiny-glade.rne` sha256 `f507a6ce…`）的 `country-core`
crate 中 `src/systems/**` 与 `src/resources/**`（共 459 个 .rs 文件）做行为级逆向：
恢复每个文件的作用、每个函数的真实业务逻辑（布局/状态机/算法/ECS 参数面），以
**文档与证据**形式沉淀，为后续源码实现阶段提供权威依据。

工作方式（用户指定，分轮次）：

1. **第 1 轮（8 域并行）**：8 个领域 agent（history/wall/session-save/
   terrain-water/ui-input/camera-time/collision-eco/audio-misc）各自批量反编译 +
   逐模块 DIGEST 文档。
2. **第 2 轮（审查+闭合）**：逐文件审查现有 reconstruction 实现（“代码写 X，
   证据为 Y”清单）+ 闭合第 1 轮 U 项；产出 FIX-LIST。
3. **第 3 轮（章节化）**：按用户指正改结构——先由 B 骨架建源码地图，再逐文件
   章节化填充（文件作用 + 逐函数 O/I/U 结论）。
4. **第 A 轮（补漏）**：审计发现 95 个未覆盖文件（render_loop/roofs-rt/
   backend-misc），3 个新域 agent 补齐；wall 域 10 个空白函数专项闭合。

## 4. 关键逆向事实（重要结论，实现阶段必须遵守）

- **游戏 Vec 布局 = cap-first**：`{cap@+0x00, ptr@+0x08, len@+0x10}`（与 std 不同）。
- **S_PUB32 只含 pub 项**；私有函数不在其中 ≠ “全内联”，先查骨架 CU
  “编译实例 RVAs” 与 .rdata CU 函数边界表（0x14369a000 等）。
- **权威索引 v3** = S_PUB32 + 骨架 RVAs（1,864 过程）；PDB 骨架名只作线索，
  机器码为准。旧 sysres v1 索引有系统性名/址错位（多域证实 10+ 处）。
- **索引层级**：v1（错位）→ v2（S_PUB32，仅 pub）→ v3（合并，当前权威）。
- 跨域全局：0x14362c420=panic 进行中标志、0x14362c3a8=日志级别、
  0x14362c011=楼梯校验开关。
- CameraMode = 核心 6 + 拍照槽 6..12；PhotoModeCameraMode 4 变体。
- 快照 schema = JSON + flate2 deflate（非 rkyv/ron）。
- WallState = 0x70B；CollisionWorld = 17×0x390B 子世界槽；WorldRaster 512² u8。
