# 批次 3：主线串行

**目标**：三个最大/最难模块按依赖顺序串行推进。

**顺序**：wall-constructor 剩余族 → decorator（最大，且依赖前者）→ toolbar

**为什么串行**：
- **decorator 依赖 wall-constructor**：门窗/烟囱/dormer/楼梯等 decorator 视觉族消费 wall-constructor 产出的墙几何、hole、砖列。
- **toolbar 依赖前面全部**：工具栏/菜单/设置界面要驱动 wall/roof/decorator 的工具模式与参数。
- 三者合计 ≈ 568 业务函数（占上层总量 ~66%），是工作量主体。

## 子顺序

1. **wall-constructor**：先 `construct_walls` / `WallConstructor` / segmentation（已有基础），再 arches / elevation_supports / lintels / fences / gates / floors / platform+playermade stairs / halftimber / plaster / utils。
2. **decorator**：先 blueprint/load/derive_subtype/apply_op 主干，再 `decorator_visual/*` 各视觉族（dormer/chimney/window/door/flag/clothline/lantern/stairs/railings/trapdoor），再 ui_systems 交互，最后 history/backup/restore。
3. **toolbar**：先 mei 框架（core/config/layout/widgets），再 toolbar_* 布局/交互，再 menu/*、photomode/*，最后 text/third_party_licenses_server。

## 出口条件（批次级）

- wall-constructor：全部结构 family（arches/pillars/brackets/turret/fence/gate/lintel/floor/stairs/halftimber/plaster）产出 96B 砖记录并有原侧对照。
- decorator：`decorator_visual/*` 全族产出视觉实体并有原侧对照；ui_systems 交互链接权威状态。
- toolbar：mei 框架 + 菜单 + photomode + text 完整可运行；工具栏能驱动 wall/roof/decorator 工具。
- 三模块都依赖 core 权威状态，若 core 侧未闭合，先在冻结契约上实现并登记，不阻塞。
